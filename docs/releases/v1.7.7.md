# v1.7.7 · 删除变成可撤销，海报编辑器到位，更新链路不再说「失败了」了事

> 本仓库自己的发布说明。相对上游 v1.6.8 的完整改动见 [CHANGELOG.md](../../CHANGELOG.md)。

这一版修掉三个用户能直接撞上的问题，补上上游 v1.7.0 的海报编辑器，
并把发布这件事从「人手动打包」挪到「CI 跑完所有门禁再打包」。

## 主要更新

- **画廊删除不再销毁文件，30 天内可还原。**
  原先删除就是 `unlink`，于是历史记录行、画布节点、已经打开的大图预览
  里所有的 URL 一起变成破图，而且没有任何退路。
  现在删除是**软删除**：条目打上 `deletedAt` 进回收站，文件原地不动；
  只有「清空回收站」或超过保留期才会真正删除。
  保留期是 `GALLERY_TRASH_RETENTION_MS` = 30 天，
  清理是**惰性**的——在 `mutateGallery` 里顺手做，
  没有定时器、没有需要在退出时收尾的东西；
  一个进程哪怕再也不会被打开，下一次启动的第一次存储调用也会把它清掉。
  另外，把一张旧副本还在回收站里的图片重新加入，
  结果是**一条看得见的新条目**，而不是静默的无操作。

- **海报编辑器（移植自上游 v1.7.0）：图片节点上叠文字与 Logo。**
  全程本地 Canvas 2D 合成，**不调用模型、不消耗额度**，底图不被改写。
  保存时把合成结果作为**新图片节点**上传，并把图层配方存进这个新节点的
  `metadata.poster`（新节点与原节点相连）。
  重新打开结果节点会还原每一层，而不是只剩一张压平的图。
  弹层里的 `Ctrl+Z` / `Delete` 只作用于海报图层，不会误删画布下面的节点。
  **画布的资产清扫现在会把这层配方算作引用**：成品节点自己只持有压平的合成图，
  底图与 Logo 图层只存在于 `metadata.poster` 里，而编辑器每次打开都要读它们。
  之前清扫只认 `metadata.asset`，于是**删掉任意一个画布**就会把用户做过的每张
  海报的底图一并删掉，再打开时是空舞台加上几个悬空的图层。

- **更新链路终于说清楚到底发生了什么。**

  | 原先 | 现在 |
  |---|---|
  | 只看 `--profile`，Desktop 传的是路径，于是落到 `web` | 依次看 `DSH_PROFILE`、`--profile`、argv 里的 `profiles/<名字>` 路径段 |
  | Desktop 环境下照样 spawn，只得到「更新失败」 | 直接给出 `update-manual-required` + 可复制的安装命令 |
  | 子进程 stderr 被丢弃，只剩退出码 | 保留末尾三行（上限 4000 字符），pnpm store 冲突、目录被锁都能看见 |

  第一行是 Desktop 用户真正那次失败的根因：Electron 宿主把 profile 当作**路径**
  传进来（`…/.dsh/profiles/desktop`），既不设 `DSH_PROFILE` 也不传 `--profile`，
  所以只按 flag 解析的实现对每个 Desktop 用户都落到 `web`——
  **哪怕更新"成功"了，正在运行的宿主插件也还是旧的**。

  Desktop 那条尤其重要：DSH Desktop 的插件目录由桌面应用独占，
  命令行去写必然以退出码 1 被拒。之前的实现仍然去 spawn，
  于是用户看到的是一句没有任何原因的失败——这正是上游 issue #41 描述的死胡同。
  现在面板会说明原因，并把安装命令和下载地址一起给出来。

- **画布有了快捷键面板。**
  按 `?` 或 `F1` 呼出，工具栏新增键盘图标入口，`Esc` 关闭（层级在所有浮层之上）。
  有快捷键的控件同时把它写进自己的提示里（如「撤销 (Ctrl+Z)」），
  所以不必先知道有这块面板才能发现快捷键。
  键位定义集中在 `CANVAS_SHORTCUTS` 一张表里，和检查脚本用的是同一份数据，
  图例不会与它记录的代码漂开。

- **损坏的海报配方会被当场拒绝。**
  `isPosterDocument()` 是严格的（`version === 1`、边长为整数且 ≤ 4096、
  64 位 hex 的 `assetId` 且带图片扩展名、`url` 走同源资源路由、
  类型字段是 `type` 而不是 `kind`、id 唯一、颜色为 `#rrggbb`），
  并且被 `isNode()` 调用——带半合法配方的画布保存会明确失败，
  而不是等到下次打开编辑器时才抛错。

- **浏览器套件不再抢调试端口。**
  它们原先用 `9900 + 随机(300)` 猜端口，两次运行（或一个残留进程）
  撞上同一个端口时就是那个偶发的 `Error: CDP down`，
  让 `verify-ui-contracts` 报 27/28。
  现在统一走 `scripts/lib/headless-chrome.mjs`：以
  `--remote-debugging-port=0` 启动，从 `DevToolsActivePort` 读回 Chromium
  真正发布的端口，检查 `exitCode`，保留 stderr 供报错使用，每次启动用独立 profile 目录。
  三个守卫共用它，并且 `verify-ui-contracts` 会扫描其他守卫的源码，
  谁再写死一个端口都会让检查变红。

- **发布由 CI 完成，不再是人手动打包。**
  `.github/workflows/release.yml` 依次跑
  typecheck → build → ffmpeg → 全部套件 → `verify-pack` → `pnpm pack`
  → `SHA256SUMS` → 打 tag → 建 Release。
  打包时带 `--ignore-scripts`，确保 Release 里那串校验和对应的字节
  **就是测试跑过的那份**，而不是重新构建出来的另一份。
  重跑是幂等的：同一个 tag、替换资产、不会产生重复 Release，也不会移动已有的 tag。
  npm 发布是另一个 job，由一个仓库变量控制开关；
  它先探测**包是否存在**再探测版本——npm 对这两种情况都回 E404，
  但只有后者是正常发布。

- **`test:negative` 并没有跑它定义的全部用例。**
  为回收站用例新增的 `canvas-video` runner 没有接进 `test:negative` 的命令链，
  于是那条用例手动跑是绿的、却永远不在门禁里。
  现在已接上，并且 `verify-negative.mjs` 在开始跑之前会先自检：
  任何一个已定义的 runner 不在那条命令里，整个反向验证直接拒绝运行。

## 兼容性

- 不新增运行时依赖，无配置变更，无需迁移。
- 画廊索引新增可选字段 `deletedAt`：旧版本的清单读进来就是「全部存活」，
  不需要迁移步骤；新版本写出的清单被旧版本读取时，
  回收站里的条目会被当作正常条目显示（不会丢文件）。
- 画布节点新增可选字段 `metadata.poster`；没有它的节点行为完全不变。
- 历史、收藏、模板、渠道设置、视频记录全部不受影响。

## 安装

```bash
dsh plugin --profile web add https://github.com/q253595422/dsh-imagegen-video/releases/download/v1.7.7/q253595422-dsh-imagegen-video-1.7.7.tgz
```

从本页的 tgz 附件安装：

```bash
dsh plugin --profile web add <下载路径>/q253595422-dsh-imagegen-video-1.7.7.tgz
```

安装后重启 `dsh web`。**DSH Desktop 用户**：桌面版插件目录由应用独占，
请用面板里给出（或上面这条）`dsh plugin ... add` 命令在终端执行，
或在「设置 → 插件」里直接安装这个文件。

## 验证

- `pnpm run typecheck` 通过；`pnpm test` 全链通过——十一道离线检查：
  `verify-tracked`（`pnpm test` 的第一步）、`verify-reproducible`、
  `smoke`、`smoke-video`、
  `smoke-canvas-video`、`smoke-video-picker`、
  `smoke-compose`（真实 ffmpeg，零跳过）、`verify-b-defect`、
  `verify-video-layout`、`verify-frame-grab`、`verify-ui-contracts`。
- `verify-tracked` 是这次发布过程中真出事才补上的一道：`.gitignore` 里
  未锚定的 `lib/` 同时匹配了 `scripts/lib/`，于是
  `scripts/lib/headless-chrome.mjs` **从未进过仓库**，而三个浏览器守卫都
  import 它——干净 clone 直接 `ERR_MODULE_NOT_FOUND`，本地却一直是绿的，
  因为文件只存在于一台机器的磁盘上。现在 `/lib/` 只匹配构建产物，
  并且每个相对 import 的目标都必须是 git 跟踪的文件，`src/` 与 `scripts/`
  下也不允许存在“既未提交也未忽略”的源码。
- 反向验证 `pnpm run test:negative` 共 **56 个变异**，
  分布在 contracts 31 + smoke 16 + video 4 + canvas-video 1 + pack 2 + tracked 1 + reproducible 1；
  每一个都让对应检查**变红**，且变红的原因与注入的缺陷一致。
  本版新增的用例包括：

  | 注入的缺陷 | 应当变红的检查 |
  |---|---|
  | 海报配方不再被校验 | `smoke`（路由级往返 + 两种损坏形态被拒） |
  | 资产清扫不认海报配方里的底图与图层 | `smoke`（删掉别的画布后，海报底图与 Logo 仍然可读） |
  | 打包声明了某个入口，包里却没有那个文件 | `pack`（`exports["./client"] -> lib/client.js (not in the archive)`） |
  | 构建按哈希表的遍历顺序序列化 CSS module 导出 | `reproducible`（两次构建的 `lib/client.js` 字节不同） |
  | 某个守卫 import 了一个从未入库的辅助文件 | `tracked`（`scripts/verify-tracked.mjs`） |
  | 删除画廊条目又直接销毁字节 | `smoke-canvas-video` |
  | 更新器又去 spawn 被锁定的 desktop profile | `smoke` |
  | `?` 键不再打开快捷键图例 | `smoke` |
  | 工具栏控件不再在提示里带上键名 | `smoke` |
  | 某个浏览器守卫又自己猜 DevTools 端口 | `verify-ui-contracts` |
  | 快捷键面板在窄屏停止折成单列 | `verify-ui-contracts` |
  | 快捷键面板不再限制高度、直接长出视口 | `verify-ui-contracts` |
  | 回收站的还原按钮不再携带各自条目的 id | `smoke` |
  | 展开的回收站又重复一遍计数标题 | `smoke` |
  | 清空回收站的确认框不再说明将删几个 | `smoke` |

- **端口那一条是源码级不变量**，排在所有浏览器检查之前执行：
  它读取 `scripts/` 下每一个会启动浏览器的脚本，
  用拼接出来的模式匹配「非 0 的 `--remote-debugging-port=`」，
  命中就直接失败——所以它不可能因为「这次运气好没撞端口」而假绿。
- 这条不变量自身也有反向用例：把固定端口写回任一守卫，`verify-ui-contracts` 必须变红。
- 浏览器相关检查在缺少 Chromium 时**明确跳过并返回成功**，
  跳过与通过会分别打印，不把「没跑」说成「通过」。

### 已知边界（诚实说明）

- **npm 包已发布（2026-10-18）。** `@q253595422/dsh-imagegen-video@1.7.7`
  已在 registry 上，`shasum` 与 Release 资产 `910d6e37…` 一致。首次发布由人工
  完成——npm 的 trusted publishing 只能挂在**已存在**的包上，所以这一步无法
  交给 CI。1.7.7 是那一次人工发布的对象：它发布时用到的清单里
  `@deepseek-ai/schemastery` 仍在 `dependencies`，这个归属问题在 1.7.8 修正。
  随后为该包配好 Trusted Publisher（`npm trust github`，仓库
  `q253595422/dsh-imagegen-video`，workflow `release.yml`，权限 publish +
  stage publish）并把仓库变量 `NPM_PUBLISH` 设为 `true`；1.7.8 是第一条只靠
  GitHub OIDC、不依赖本机 npm token 发出去的版本。
- **Desktop 的更新仍然是手动的**，这是上游 CLI 的设计，不是本插件能绕过的；
  本版做到的是**不再假装能自动更新**，并把可执行的命令交到用户手上。
- 海报编辑器只做文字与 Logo 两层合成，**不是完整的排版工具**：
  不提供旋转、渐变、阴影、多行富文本。它的定位是「不花额度的一层叠加」，
  复杂的成图仍应回到生成链路。
- 回收站保留期固定为 30 天，本版不提供设置项。
