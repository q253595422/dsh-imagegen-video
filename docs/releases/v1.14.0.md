# v1.14.0 — 代码生成：对话模型写程序，本机渲染成片

一句话概括：画布合成栏多了一个「生成方式」选项。选「代码生成」后，DSH 里已经在用的对话模型写一段绘图程序，本机把它渲染成视频或图片——**不需要任何生图或生视频模型**。「模型生成」原样保留，仍是默认值，两条路每个任务各选一次。

## 为什么

生图和生视频都受两件事约束：要有额度，要等上游。而有些画面——标题卡、数据动图、几何转场、确定性的图表动画——用代码直接画出来更快、更准、更便宜，也更容易复现。DSH 里本来就有对话模型，缺的只是「让它写程序、由本机执行」这一段。

## 做了什么

- **每任务选择，不做全局开关**：入口在现有合成栏里（`生成方式` 下拉），状态只活在当前画布，不写设置、不落盘。选「代码生成」时该分支的模型选择器隐藏，比例 / 分辨率 / 时长保留——它们照常决定输出。
- **走宿主已有的模型，不新增配置**：`ctx.inject(['skills','agents'])` 拿到宿主的 `agents` 与 `agentPresets`，用 `ctx.agentDefaultModel` 的当前选择组一次无头回合：系统提示放绘图 API 与约束，用户消息就是那句描述，回合结束读最后一条助手文本。**不是**插件设置里的「提示词增强模型」，也不需要新密钥。没选模型时报 `code-no-chat-model`。
- **沙箱执行**：`node:vm` + `Object.create(null)` 上下文，2 秒编译超时 + 整次渲染 deadline（默认 120 秒）。上下文里没有 `require` / `process` / `fs`，只有一套固定的绘图方法（矩形、圆、路径、渐变、文字、图像的像素级操作）。生成源码上限 60000 字符。
- **渲染**：逐帧得到 RGBA 缓冲，视频写进 ffmpeg 的 stdin 编成 MP4（`libx264` + `yuv420p`，可直接播放，也能被 `clip-compose.ts` 拼接）；图片用自写的 PNG 编码（IHDR/IDAT/IEND + CRC32 + `zlib.deflateSync`）直接落盘，零原生依赖。
- **产物对等**：不新开队列，不新开存储。请求只多一个 `renderer: 'code'`，其余照旧走 `GenerationRequest` / `VideoGenerateRequest`，因此占位节点、轮询、取消、重试、历史、画廊、取尾帧、多选拼接、时间线裁剪与转场、工作流执行器**全部直接复用**。视频条目与图片条目都带 `renderer: 'code'` 与 `renderSource`。
- **唯一的额外路由是只读的**：`POST /api/dsh-imagegen/code/probe` 回答「会渲染成多大、多少帧、本机有没有 ffmpeg」，不调模型、不渲染。故意**没有** `code/render`——两条生产入口迟早会让占位/取消/重试各写一遍并漂移。
- **降级而不是死路**：模型回了一段散文而不是代码时，改用内置标题卡渲染，任务标 `degraded` 并记原因；`code-not-code` 只用于拿不到可执行内容的情况。

## 失败语义

节点上直接显示宿主原文，并在下方补一行「可在上方「生成方式」里切回模型生成后重试」。

| 错误码 | 触发条件 |
| --- | --- |
| `code-prompt-empty` / `code-prompt-too-long` | 描述为空 / 超过 4000 字符（路由边界拦，不调模型） |
| `code-no-chat-model` | DSH 里没有选中的对话模型，或 `agents` 服务不可用 |
| `code-chat-failed` | 回合失败（鉴权、网络、上游报错），报文带宿主持久化的失败原因 |
| `code-not-code` / `code-syntax` | 模型没给出可执行代码 / 代码编译不过 |
| `code-runtime` | 逐帧执行抛错，报文标明第几帧 |
| `render-timeout` | 超过 120 秒 |
| `render-no-ffmpeg` | 找不到 ffmpeg（含 `FFMPEG_PATH` 候选），提示安装方式 |
| `render-cancelled` | 用户取消 |
| `render-encoder-died` / `render-encoder-failed` / `render-empty` | ffmpeg 异常退出 / 无输出 |

缺 ffmpeg 会在**提交前**预警（`code/probe`），且只影响视频——图片路径不需要 ffmpeg。

## 重试

生成出的绘图程序存在任务上。重试一次**渲染失败**的任务会沿用同一份源码，不再问模型；想换一版就重新生成。

## 验证

- `pnpm run typecheck`、`pnpm run build`、`pnpm test` 全绿。
- `node scripts/smoke-code-render.mjs`：13 项，含真实 ffmpeg 出片（ffprobe 复核 1280×720 / 30fps / ~3s）、真实 PNG（校验签名与 `1080x1080`）、代码片段进入 `createClipComposer()` 拼接出带 `ftyp` 的 MP4，以及宿主 seam 的正常与三类失败（无 `agents`、无模型、回合 `turn/end` 为 error）。
- `scripts/smoke.mjs` 里补了画布交互用例：默认「模型生成」、切到「代码生成」后模型选择器消失而比例/分辨率/时长保留、提交体带 `renderer: 'code'` 且 `model` / `channelId` 为空、占位节点带 `renderer`、失败节点显示错误码与切回提示、切回后模型选择器回来。

## 依赖与边界

- 新增依赖：**无**。ffmpeg 仍是唯一外部工具，仅视频路径需要。
- 代码路径不参与导演规划：代码本身就是规划。
- 代码渲染是 CPU 任务，视频队列并发为 1，与模型渲染串行；`MAX_PIXELS` 限 4096²。
