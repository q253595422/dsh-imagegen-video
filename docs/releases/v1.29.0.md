# v1.29.0 — 插件改名「团团TV」；入口可被扫描器验证；侧栏适配 DSH 0.2.2

本版把插件在界面上显示的名字定为**「团团TV」**，同时修掉三件「装上但看起来没生效」的问题：插件清单声明的运行时入口在仓库里并不存在（第三方收录扫描器因此判它没有 `apply`）、侧栏入口与历史区在 DSH 0.2.2 上被新布局挤掉、以及没有版本变更的推送被当成发布事件让 `main` 变红。

包名 `@q253595422/dsh-imagegen-video` 不变（npm 的包名不允许中文，也不该为了改显示名去动它），改的是用户看到的那一层。

## 显示名与品牌

- **插件详情页的标题此前是完整包名。** 原因不在包名写错了，而在标题来源：宿主读插件包 `locale/<语言>.json` 的 `meta.title`，**没有声明这个字段时回退到 manifest 的 `name`**。本仓库两个语言文件当时只声明了 `meta.description`，于是标题一路回退成完整包名。
- 现在 `locale/zh.json` 声明「团团TV」，`locale/en.json` 声明 `TuanTuan TV`，宿主按当前界面语言取对应值。
- **三语品牌文案统一**：`entry.label`（侧边栏入口）、`panel.title`（工作台面板标题，原为 `VisioWork`）、`settings.title`（设置卡标题）、`config.disabledTitle`（停用提示）在 zh / en / ru 里改成同一个名字。此前三处各写各的（`AI 生图`、`VisioWork`、`Image settings`），互不一致。
- **Agent 指导文案与 `/edit_image` 成功提示**同步改用新名；指导文案保留包名，以免模型对不上实际安装的模块。
- README 标题改为产品名，正文标注实际包名。
- **插件图标入库**：`icon.png` 此前只在本机、没有提交，`package.json` 也没有 `icon` 字段；现在两样都有，并进 `files`，详情页才拿得到图标。
- **刻意不改**：设置分区名「生图配置 / Image settings / Настройки генерации」。它是**位置名不是品牌名**——后端有 22 处错误提示写着「请打开设置 → 生图配置」，改它得成批同步那些提示与三条测试断言，而它本身不承担品牌职责。

## 包入口：声明的文件必须在仓库里，也必须真被 `files` 装走

两件相关的事，都是「清单说有、包里有」与「清单说有、磁盘上没有」的区别。

- **`main` / `exports["."]` 改指仓库根目录的 `index.js`。** 它们此前指向 `lib/index.js`，而 `lib/` 是构建产物、被 gitignore。只读源码树的地方——不先跑 `pnpm build` 的干净克隆、按清单检查入口的包扫描器——拿到的是一个声明了却不存在的文件：清单说有运行时入口，磁盘上没有，自然读不到 `apply(ctx)`。第三方收录扫描器正是这样判的，`DSH_RUNTIME_APPLY_MISSING` 让 DeepSeek Harness Plugin 一项丢 5 分。现在根目录 `index.js` 是两行再导出（`export *` 加一行显式 `export { apply }`），跟着仓库走；`files` 同时装 `index.js` 与 `lib/`，发布包里两半都在。**实测同一版本扫描器本地从 77/100 升到 85/100**，DeepSeek Harness Plugin 一项从 15/20 到 20/20，剩余 finding 只剩两条超 16 MB 的演示视频（不扣分）。
- **`verify-pack` 现在按声明入口逐个追问「这条入口是不是被某条 `files` 条目自己覆盖」。** 此前只问「包里有没有」，问不出来：npm 和 pnpm 总会把 `package.json`、README、LICENSE、`main` 指的文件无条件打进包，所以从 `files` 删掉 `"index.js"`，`verify-pack` 依旧全绿、103 entries、`index.js` 还在包里——靠的是打包器替 manifest 兜底。这层兜底在 `main` 改名、或换成严格读 `files` 的打包器时就消失，而入口静默消失的后果是「装上了、什么都没发生」。目录条目覆盖其下所有文件、文件条目覆盖自身、通配符按段顺序匹配；打包器无条件附带的几个文件按名字豁免。新增负向用例钉住它：从 `files` 删掉 `index.js`，check 必须以「entry points that `files` does not ship: main -> index.js」变红。

## 侧栏入口与历史区适配 DSH 0.2.2（#35）

DSH 0.2.2-rc.2 在侧栏列与 `sidebar.workspaces` 槽之间新增了 `scrollRegion > scrollArea` 两层结构，插件仍按旧结构定位，导致三处问题：侧栏入口不可见、点击被工作区行的行内动作抢走、历史区只占半截。

- `sidebarRoot()` 改为从 workspace 槽向上找「同时包含全局 New Session 按钮」的最近祖先；动作被隐藏时退化为与品牌锚点的最近共同祖先。
- `newSessionButton()` 排除 `[data-slot="sidebar.workspaces"]` 内的工作区级行内动作。
- `markBlocks()` 为嵌套容器补 `data-dsh-imagegen-sidebar-hide` 标记，只隐藏与 region 同级的 panel nav，保留 region 里的 history host。
- `panel.module.css` 新增嵌套分支的隐藏规则；生图态把 `[data-sidebar-scrollport]` 最后一行改为 `minmax(0, 1fr)`。
- **手机端抽屉遮挡**：窄屏检测到 `[data-sidebar-drawer="true"]` 打开时，点击「会话 / 生图」标签后调用宿主的 `[data-sidebar-toggle]` 收起抽屉，不再被抽屉盖住。
- `scripts/smoke.mjs` 新增 D3b 回归用例。

## 构建：可复现性在 rolldown 1.3 上曾静默失效

`tsdown` 升到 0.23.7 会解析到 rolldown 1.3，它把模块 banner 从 `//#region <id>` 改成了不带标记的 `// <id>`。`renderChunk` 里只匹配 `//#region` 的正则因此一条都匹配不上，`node_modules` 的 realpath 前缀原样进入产物——同一份源码在另一个目录构建出的字节不同，正是 `verify-reproducible.mjs` 抓到的「ROOT 8192f4ba / mirror b93c4594」那种不一致。**这条正则此前只在 1.1 上验证过，1.3 换格式后是静默失效而非报错**，所以升级依赖顺手把它修了。现在两种拼写都归一化；第二段正则把 `// ` 与 `node_modules/` 之间的前缀限制成不含空白与冒号的路径片段，避免误伤普通注释里出现的同一串路径（不加这个约束时实测会误伤）。

## 发布流程本身

- **没有版本变更的推送不再当成发布事件。** 原来的闸门把「`package.json` 变了」当成「要发布」，但依赖升级也改 `package.json`、action 升级也改 workflow 文件——九个 dependabot PR 全是这种情况。合并它们会触发 Release，版本仍是已发布的旧号、tag 指向旧提交，闸门必然报错，`main` 从此变红，而那次推送里根本没有新版本可发。现在「这次推送是不是发布」提成独立的 `preflight` job 用 `needs` 控制，判定顺序为：tag 不存在→发布；tag 正好指向本次提交→发布；`replace_released_assets=true`→发布并告警；**本次推送没改 `version` 字段→跳过且不失败**；改了 `version` 却撞上已发布号→失败（真错，不许覆盖旧资产）。第四条用 `github.event.before` 取推送前的版本比对，merge / squash / 直推都适用。
- **新增 HOL 插件扫描器自检 workflow。** 收录 PR 通过后扫描器建议把同一固定版本接进本仓库 CI（没有这条的条目会在 registry trust score 上扣 10%）。新文件取自官方模板，checkout 换成本仓库其他 workflow 的同一 pin（v7.0.1），权限只有 `contents: read`、checkout 不保留凭据，扫描器 action 固定到 v1.2.806（内部再固定 wheel 的 SHA-256 与 PyPI provenance）。它是 **advisory**：`min_score` 钉在收录门槛 75、`fail_on_severity: none`，真正的门禁在目录仓库那边。
- 依赖升级：`tsdown` 0.23.7、`lightningcss` 1.33.0、`@types/node` 26.6.6、`@deepseek-ai/dsh-client-connection` 与 `dsh-client-ui-renderer` 到 0.1.2-rc.1；actions 四处大版本（checkout 7.0.1、setup-node 7.1.0、upload-artifact 7.0.2、download-artifact 8.0.2、pnpm/action-setup 6.1.1）。

## 测试

- 新增 D3b（侧栏入口在 0.2.2 结构下可见、历史区高度正确）。
