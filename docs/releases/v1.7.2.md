# v1.7.2 · 视频节点此前根本无法保存

> 本仓库自己的发布说明。相对上游 v1.6.8 的完整改动见 [CHANGELOG.md](../../CHANGELOG.md)。

**带视频节点的画布存不下来。** 宿主的画布节点守卫只接受
`image` / `text` / `file` / `config`，而 `CanvasNodeType` 里还声明了 `video`，
于是 `coerceDocument` 返回 undefined，`save()` 报 `malformed canvas document`。
视频节点是本仓库的头号功能，这让它从端到端不可用：放一个片段上去，画布就停止保存。

没有套件发现它，是因为画布视频套件对 `/canvas/save` 用的是记录 payload 的桩，
真实守卫从未在视频节点上跑过。`smoke.mjs` 现在会把视频节点在三种状态下
（成片、渲染中、失败）经**真实路由**与**真实 store** 往返一遍。
把 `video` 从守卫里去掉，这条检查就会以用户当时看到的那个错误失败。

## 主要更新

- **全屏片段预览会标记失效的片段**，而不是成为「再点一层还是坏播放器」。
- **失效片段标记现在会被重载、单删、批量删除与重新生成清除。**
  重新生成此前会让节点继续宣称片段已丢失，即使新片段已经落地；批量删除会留下标记，撤销后又出现。
- **模板收藏与模板列表的记忆按读取时的数据根做键。**
  两者原本是模块级的，会活得比被重新指向的数据根更久，
  于是改 `localStoragePath` 之后可能读到旧根、写回新根。

## 兼容性

- 不新增运行时依赖，无需迁移。
- 此前因该缺陷而无法保存的画布，升级后可直接保存；已经写坏或未落盘的状态需要重新编辑一次。

## 安装

```bash
dsh plugin --profile web add https://github.com/q253595422/dsh-imagegen-video/releases/download/v1.7.2/q253595422-dsh-imagegen-video-1.7.2.tgz
```

从本页的 tgz 附件安装：

```bash
dsh plugin --profile web add <下载路径>/q253595422-dsh-imagegen-video-1.7.2.tgz
```

## 验证

- `pnpm exec tsc --noEmit` 通过；`pnpm test` 全链通过（七个套件）。
- 新增的 `smoke.mjs` C10c3 走真实路由 + 真实 store，覆盖视频节点的成片 / 渲染中 / 失败三态，
  并通过 `/canvas/read` 回读确认。
- 反向验证：把 `video` 从 `canvas-store.ts` 的守卫里删掉，C10c3 立刻失败，
  错误正是用户看到的 `malformed canvas document`。
