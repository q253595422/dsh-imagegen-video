# v1.35.1 — 构建工具链换到 TypeScript 7，上传路径的字节更严格

> 这一版没有新面板、没有新协议，也没有新增任何用户可见的功能。它发出去的原因是：v1.35.0 之后主干上留下的改动，会实际进入你下载到的 tgz，而那批改动只通过了当时的测试，没有以发布产物的形式交付过一次。

## 上传图片的字节先复制一份再交给 Blob

`src/engine.ts` 的三个多部分上传点（Nano Banana 兼容网关的单图、多参考图的 `image[]`、其余网关的单图）原来直接把 `Buffer` 塞进 `new Blob([...])`，`src/client/outfit-generation.ts` 的 `loadReference` 则把流式读到的 chunk 数组直接交给 `Blob`。

TypeScript 7 把类型化数组的 buffer 收窄成 `ArrayBufferLike`，而 `BlobPart` 要求背后是具体的 `ArrayBuffer`。现在这三处都先复制到一个恰好等长的 `Uint8Array`，再取它的 `.buffer`。

**行为上没有变化**：复制出来的字节与原字节相同，上传的内容一字不差。代价是每个上传的图多一次内存复制——在 kilo 到 mega 级别的参考图上，这个开销在任何一条上传链路里都不显著。

## 验证

`pnpm install --frozen-lockfile`、`pnpm run typecheck`（TypeScript 7.0.2）、`pnpm run build`、完整 `pnpm test` 链（69 步，含全部 UI 契约断言）、CI 里那组独立门禁（`smoke-canvas-geometry`、`verify-outfit-task-gate`、`verify-negative-anchors` 的 286 条锚点、`verify-check-harness`、`smoke-canvas-bundle`、`smoke-canvas-agent`、`smoke-listing-copy`、`conversation-sync.test.mjs`、`verify-script-entries`）以及 `verify-pack`，全部通过。

除静态门禁外，还把这个 tgz 装进一个独立的 DSH 宿主实际启动过一次：14 个插件入口全部注册进 cordis 配置，客户端注入链里能取到 `client.js`，启动日志无错误。

## 已知的边界

宿主 SDK 的版本矩阵在这次发布前就不一致：`dsh-llm` 与 `dsh-api-remotes` 现在是 `0.1.2-rc.1`，其余十来个 `dsh-*` 仍是 `0.1.2-alpha.2`，`dsh-credentials` 是 `0.1.7-rc.2`，`dsh-util-*` / `dsh-client-ui-primitives` 是 `0.2.1-rc.2`。这一版没有让它变差，也没有把它统一起来——两者都只影响类型层，不影响运行时行为，但「CI 绿」不构成矩阵一致的证据。若要统一，是一个独立于本版的改动。
