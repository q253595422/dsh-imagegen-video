# v1.35.0 — 生成出来的东西能走完最后一公里

> 这一版没有新面板。三件事都是「东西已经生成好了，却卡在最后一步」：结果图拉不下来、预设找不到官网、画布上做出来的片子回不到剧集目录。加上导演台换了身体，设置页拆成了两半。

## 结果图下载中途断流，不再等于白花钱

网关给的是 CDN 链接而不是 base64 时，`arrayBuffer()` 只有一个结局：连接断在中途，前一次已经付过费的生成就是一张截断的图。换个网络重来时，又从字节 0 开始，一个限流的 1.5 MB 图片永远落不了地。

现在按 Range 续传（`src/engine.ts` 的 `downloadResultImage`）：保住已经收到的字节，只向服务器要缺的那一段。6 次尝试、单次 45 秒、总预算 180 秒；收到 `416` 且已有字节覆盖了它的 total，就直接认定完成而不是报错。

更麻烦的一种是「HTTP 200，body 却提前关了」——长度字段看着对，字节数也对不上容器。所以下载完还按签名校验：PNG 要找到 `IEND`，JPEG 要 `FFD9`，WebP 的 RIFF 长度要对得上文件长度，GIF 要 `0x3b`。不完整的会被判为不完整、接着续传，而不是当成成品写进历史。

三条断言在现场（`smoke.mjs` 的 `B1b3`）：第一次只发一半、第二次必须带 `Range: bytes=<half>-`、最终字节与源图逐字节一致。

顺带把 CloseAI 渠道改成要 `response_format: b64_json`。它那个临时结果域 `tuye.closeai.hk` 在一些网络里根本连不上，而生成本身是成功的——与其传一个连不通的 URL，不如直接让网关把字节放回响应里。其他 OpenAI 兼容渠道保持原来的输出形状，`B1b2` 里有一条断言盯着「别的渠道不能跟着变」。

## 预设卡片带上了官网

每个预设在卡片底部多一行「官网 ↗」，新标签页打开；订阅类预设的「点击登录」跟它并列。结构上从单个 `<button>` 改成 `div > button + foot`——`<a>` 不能嵌在按钮里，那样点链接会先触发选中渠道。

新增 **Nbility · MiniMax-H3** 预设（`https://api.nbility.ai/v1`）。这条协议前几版就实现了，缺的只是一个能点出来的入口：提交 `POST /v1/videos`、轮询 `GET /v1/videos/{id}`、固定 768P，本地图会先传 `/v1/media/uploads` 换成公网地址，参考图最多 9 张。

MiniMax-H3 的时长档位从默认的两档改成 **5 / 10 / 15 秒**。上游接受 1–15 的整数秒，原来那两档把长片那一端整个藏掉了。

CloseAI 预设的显示名从「yeahzi 官逆图像（CloseAI）」改成 **CloseAI**，并提到列表首位。渠道判定认的是预设 id `yeahzi-closeai` 和 hostname，与显示名无关，改名不影响已有的渠道。

## 画布上的成品能写回剧集目录

分镜板到画布这条线（v1.33 的「一键铺板」）现在有了反方向：板子上多一个「写回文档」，确认卡先说清楚会落几个文件、改几行，写完之后逐条报「成了 / 已存在 / 坏了」。

三层分工：`drama-writeback.ts` 是纯函数，只算要写什么（`SHOT-…` → `制作成果/video/SHOT-….mp4`、设定板 → `images/IMG-….png`）；`drama-write.ts` 只管落盘，路径必须在 `<剧集>/制作成果/` 之下，默认不覆盖、覆盖前留 `.bak`、临时文件加 rename 原子写；`drama-writeback-run.ts` 接两层，取字节、抽帧、逐条写，最后才改文档。

起始帧登记成 png 而不是 mp4——`REF-` 只收图片，写 mp4 进去上游读不了。抽帧、标题与字段行、用例运行器这三处原本各写了一份副本，这次换成仓库里已有的那一份（`frame-grab.ts`、`storyboard-markdown` 的 `shotHeadingOf` / `fieldOf`、`lib/check-harness`），读写两侧各留一份最容易出现「板子上有这一镜、回写却报 missing」。

顺手修掉一个让整条链静默失效的缺陷：`storyboardOf()` 是白名单式重建，`source` 字段没被带出来，于是「写回文档」按钮的渲染条件永远不成立——那个按钮一次都没出现过。

## 导演台的默认角色换成标准蒙皮

角色默认从程序化木偶换成 **CC0 MakeHuman / CharacterCreator 标准蒙皮底模**（53 骨，含脸、手指与鞋），材质统一为灰白膜，服装用同色系 clay。旧的程序化木偶保留为「轻量木偶」回退和无 WebGL 时的 2D 路径。

用 `pose-rig` 的 17 关节方向驱动 53 骨主骨，身体与每件服装各自重定向；不为手指和面部假装做捕捉。GLB 走宿主的 `stage-assets` 只读路由，首次渲染先出木偶、加载完成后切换；导出会等标准体就绪，5 秒超时回退木偶。

资产只取 MakeHuman 导出的 GLB，不含 CharacterCreator 的 GPL 源码，署名见 `THIRD_PARTY_NOTICES.md`。

## 设置页拆成生图与生视频两个模块

设置卡片分成「生图 / 生视频」两块，各自有三步引导、模块标签和模型预览。分镜板可以直接选视频模型与渠道，并按所选模型收窄时长与分辨率——选到只支持 768P 的模型，就看不到别的档位。
