# v1.24.0 · Google 原生渠道协议；URL 型模板图不再 404

> 各版本改动见 [CHANGELOG.md](../../CHANGELOG.md)。

## Google 原生渠道协议（#28）

渠道的「接口协议」新增 **Google 原生**：用 Google API Key 直连 Generative Language
的 `:generateContent`，不再要求中转站把 Gemini 包成 OpenAI 兼容接口。

- **请求整形**：`contents[].parts` 携带提示词与参考图（`inlineData`，最多 5 张、每张
  ≤10MB）；`generationConfig` 固定 `candidateCount: 1`、`responseModalities: ['TEXT','IMAGE']`，
  比例与清晰度嵌套在 `imageConfig`（`aspectRatio` / `imageSize`），auto/空值省略不发。
  鉴权走 `x-goog-api-key` 头，不发 Bearer。
- **URL 容错**：配置地址带 `/models`、`/models/<id>:generateContent` 或 `/interactions`
  后缀时自动剥回版本基址再拼目标端点；query/hash 不随请求发出。
- **模型检测**：google-native 渠道支持「检测模型」（GET models 列表，解析 `name`
  字段并剥 `models/` 前缀，只保留图像模型）；完整 URL 模式下检测按钮不再禁用。
- **数量与响应**：body 不带 `n`，多张由并行单图请求满足；响应跳过 `thought` 部分，
  兼容 `inlineData` / `inline_data`，缺 mimeType 按字节嗅探；空结果报
  `promptFeedback.blockReason`。
- **GIF 前置拒绝**：Gemini 图像模型不出动图，google-native 渠道的 GIF 请求在网络调用
  之前报错（`gif-protocol-unsupported`），不会静默降级成静图照常计费。
- **预设与文案**：新增「Google Gemini 官方（原生）」预设
  （`https://generativelanguage.googleapis.com/v1beta`，预填 gemini-3-pro-image /
  gemini-2.5-flash-image）；协议选项与提示文案补齐 zh/en/ru 三套。参考图上限对
  google-native 给 5 张（此前 gemini id 落 nanobanana 族只给 1 张）。

## URL 型模板图修复（#29）

工作室「灵感案例」墙里 itgoyo / evolink / songtianlun / prompt-signal / handraw 五个
URL 型源的缩略图全部 404：`imageFileFrom` 的空段校验把解码后 `https://` 里的 `//`
判成空段，引用恒死在路由层，到不了主机白名单。

- 仅对模板路由放行 URL 型引用：空段不再拦截，复合路径上限 400 → 4100（对应 store
  侧 4000 字符 URL 上限 + sourceId）；`.` / `..` / 绝对路径 / 反斜杠 / NUL 照旧拒绝，
  主机白名单仍由 templates-store 兜底。
- 其余图片路由（history / gallery / canvas / model）保持严格校验，不受影响。

## 已知边界

- google-native 未做真实 Google 上游的付费验证（无 API Key）；请求/响应形状按官方
  API 与仓库内 Antigravity 既有 Gemini 原生实现核对，桩 fetch 套件覆盖各分支。
- 预设不带协议字段：从「Google Gemini 官方（原生）」预设建渠道后需手动把接口协议选为
  「Google 原生」（预设提示文案已说明）。
