# v1.15.3 — 视频工作室不再是死路

一句话概括：进了「生视频」能回得来，回不来的时候至少还有一条能点的路。

## 为什么

这一版修的是两个叠在一起的死路。它们单独看都不致命，叠起来把用户困在一个怎么点都没反应的页面上。

**第一处：进得去，出不来。** 外壳在视频标签页上会把生图参数侧栏整块隐藏（两块输入面板不能同时出现），而侧栏正是「文字 / 编辑 / 视频」三枚切换 pill 唯一的渲染位置。于是一旦切到视频，界面上就不存在任何回到生图的控件——不是难找，是根本没有。用户唯一能做的只有刷新页面，或者绕去图库再从那里回来。

**第二处：点得动，但不发生。** 顶部导航里「普通生图」那一项看起来是常态可点的。但视频标签在工作区映射中被算成索引 0，与「普通生图」撞在同一个索引上；`GooeyNav` 的选择函数在 `index === activeIndex` 时直接 `return`，而这个 `return` 连回调一起吞掉了——它本意只想跳过那一下果冻动画。结果就是点了没有任何反应，也没有任何提示说明为什么。

两处叠起来的实际体验是：**屏幕上所有看起来能返回的东西都点不动。** 这也解释了为什么它此前没被发现：现有的布局守卫里没有 `videoToolbar` / `videoBack` / `videoEmpty` 这几个 fixture，`GooeyNav` 的点击回调则完全没有测试覆盖。

## 做了什么

- **工作室自己带一条出路。** `VideoPanel` 新增可选 `onExit`，在标签页自己的工具栏首位渲染一枚「← 返回生图」按钮，由父组件传入（切换工作区/标签的状态在父组件里）。按钮**只定义一次、被两个 return 分支共用**——尤其是「没有可用视频模型」那条分支：一个满屏只有提示文字的页面，恰恰最需要出口。
- **导航短路只作用于动画。** `select()` 改为「果冻动画只在真正换页时播放，`onSelect` 无条件调用」。点击与键盘走的是同一个函数，所以两条路径一起修好了。
- **三语文案。** `video.back` 进了 zh / en / ru，沿用现有键名风格与两空格缩进。

## 验证

- **全量测试**：`pnpm test` 20 个脚本全绿（`EXIT=0`），`verify-reproducible` 断言两次构建的 4 个产物逐字节相同。
- **真浏览器**：现有布局守卫的 fixture 里没有视频工具栏，所以另写了一支在真 Chrome 里量的检查——按钮 92×28、`pointer-events` 未被遮挡、CDP 真实鼠标按下能到 handler、空状态文案没有被新工具栏挤掉。
- **点击契约**：`GooeyNav` 此前零覆盖，补了 jsdom 真渲染 + 真 `dispatchEvent` 的五个场景（当前页点击、换页点击、Home、ArrowRight、越界 activeIndex）。关键是**做了反向对照**——把修复回退成旧的 `if (index === activeIndex) return`，测试立刻报出 2 条失败；恢复后全绿。这证明这几条断言确实在看这件事，而不是必然通过。

## 一处被撤回的改动

`.videoEmpty` 的 `height: 100%` 一度被改成 `flex: 1; min-height: 0`，理由是「新增 28px 工具栏 + 14px 间距超过了 100%，会溢出被裁」。

对照实验否定了这个推理：两种写法在 420px 与 150px 两种视口下测出的数字完全一致（`scrollHeight == clientHeight`，元素底边都正好落在内容边界上）。原因是 `.videoWorkspace` 的 `overflow: hidden` 配合 flex 默认的 `min-height: auto` 已经把状况吃住了。改动没有收益，已恢复原样——本版 `panel.module.css` 的新增只有 `.videoBack` 两段。

## 影响面

`onExit` 是可选属性，不传就与改动前完全一致，其他挂载点不受影响。`select()` 的语义变化只影响「点击当前已选中的标签」这一种此前无任何效果的交互。不改变任何接口、数据结构或持久化格式。
