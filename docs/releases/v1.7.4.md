# v1.7.4 · 三条「用户看得见、但只在特定时序下才发生」的修复

> 本仓库自己的发布说明。相对上游 v1.6.8 的完整改动见 [CHANGELOG.md](../../CHANGELOG.md)。

三条都是失败率问题：不容易撞上，撞上一次就没有绕过的办法。

## 主要更新

- **一个上游拒绝保存的产物，不再让整次技能运行白跑。**
  画布技能（比如「图片拼成 PPT」）会把跑出来的文件逐个交给宿主保存，
  而宿主对扩展名和大小有硬拒（`.svg`、`.html` 这类不允许，超过 50MB 不允许）。
  以前其中一个产物被拒，异常会一路冒到整次运行：前面已经跑好、
  也已经写进画布的东西全部不算数，用户只看到一条错误。
  现在被拒的那个产物会被跳过，其余产物照常入画布，
  并给出一条三语警告，指名道姓说清是哪个文件、为什么没保存。
- **片段文件的读取流挂掉，不再把整个 DSH 进程带走。**
  播放一个片段时宿主是把文件 `pipe` 给响应的；`pipe` 只会把错误转给**目的地**，
  永远不会转给来源流——所以文件句柄在管道中途出错时，
  未处理的 `error` 事件会直接终止宿主进程（整套 Web GUI 一起没）。
  现在来源流挂了独立的监听，出错时干净地断开一个响应，而不是杀掉进程。
- **切画布不再丢失刚做的改动，也不再被上一个画布的迟到答复覆盖。**
  自动保存是防抖的，所以「改完标题立刻切到另一个画布」这个动作
  曾经有两种坏结果：改动没来得及写就切换，于是**静默丢失**；
  或者旧画布的保存答复晚到一步，落到屏幕上**把新画布顶掉**。
  现在每次写入带序号，落后于当前编辑的答复一律丢弃；
  切换/新建之前先把待写的改动冲刷下去；删除画布时会记下这份文档已对账，
  避免随后的切换把刚删掉的画布又写回去。

顺带修掉的一处：

- **视频工作台提交/取消之后，列表要等一整个轮询周期才更新。**
  任务列表由父组件统一轮询（这样画布和视频页签看的是同一份状态），
  但页签自己的刷新函数在受控模式下直接返回，于是用户点了「生成」或「取消」，
  要等满 5 秒才看到那一行出现或变成已取消。现在这个请求向上走，
  交给父组件那唯一一个轮询器去重新读取，不新增第二个轮询循环。

## 兼容性

- 不新增运行时依赖，无需迁移，无配置变更。

## 安装

```bash
dsh plugin --profile web add https://github.com/q253595422/dsh-imagegen-video/releases/download/v1.7.4/q253595422-dsh-imagegen-video-1.7.4.tgz
```

从本页的 tgz 附件安装：

```bash
dsh plugin --profile web add <下载路径>/q253595422-dsh-imagegen-video-1.7.4.tgz
```

## 验证

- `pnpm exec tsc --noEmit` 通过；`pnpm test` 全链通过（七个套件全部 OK，
  其中 `smoke-canvas-video` 的 ffmpeg 真实编码路径没有跳过）。
- 三条主修复各自都有能复现原缺陷的检查，并做了反向验证：
  把修复去掉后对应的检查会**变红**（不是「看起来做了」）。
  - 被拒产物：把异常重新抛回去，检查立刻报出
    `the task failed with error 出于安全考虑，不支持上传 .svg 文件`。
  - 迟到答复 / 切换前冲刷：去掉守卫后分别报
    `a late answer for the canvas the user left is discarded`
    与 `the pending edit was flushed before the canvas was replaced`。
  - 视频列表刷新：去掉上行调用后报
    `submitting asks the parent to re-read the queue (reads: 1 -> 1)`。
- 片段读取流的修复由真实 HTTP 竞态检查覆盖（真起服务、真发请求、真断流）。
