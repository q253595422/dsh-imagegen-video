# v1.22.2 · 侧栏：生图态也有收起和展开键，标签栏对齐宿主

> 各版本改动见 [CHANGELOG.md](../../CHANGELOG.md)。

这一版只动侧栏。四件事：生图态的两个控件先后被插件自己的规则吞掉、被自己的层级盖住，
「会话 / 生图」标签栏和宿主的「新建会话」按钮对不齐，标签栏虽然有了 `role="tab"`
却没兑现这个角色承诺的键盘契约。

## 生图态：收起键回来了

macOS 宿主把「收起侧边栏」放在 **logoRow 之上的一条窗口 chrome 条**里（`topStrip`，
那是为了避开左上角红绿灯）。那条 chrome 条不拥有任何 slot 锚点，于是被插件「生图态
隐藏外来条目」的规则一起 `display: none` 了。

后果不只是按钮消失：chrome 条被隐藏后 logoRow 上移，品牌 logo 被压在红绿灯底下。
收起之后只剩 ⌘B 能回去。

现在按**可访问名**（中英文四个词）认出宿主自己的折叠控件，把它所在的 root 直接子块
并入 chrome 白名单，跟随宿主一起保留。

> **为什么按名字认、不按类名认：** 宿主的类名是构建哈希（当前是 `kB3qhq_`，上个版本
> 还是 `_3WPZCG_`），升级就变。`aria-label` 是宿主对外承诺的可访问名，稳定得多——这也是
> 本仓库「CSS 不猜哈希类名」那条约定在 JS 侧的对应做法。

> **可见性只用来择优，不用来过滤。** 候选块如果被插件自己的规则隐藏了，它必须还能被
> 再次认出来。按可见性过滤会让标记一次性失败之后永远认不回来，按钮就永久弄丢——
> 那种自锁比原来的 bug 更难查。

## 生图态：展开键也回来了

收起之后，宿主会在窗口左上角挂一个 **`[data-shell-leading]` 座位**，里面是「打开侧边栏」
和「新建会话」。这个座位是 `z-index: 15`。

问题在于插件接管中心列用的是 `z-index: 60`（`--z-takeover`）。于是：

| 状态 | 插件视图 | 展开键 |
| --- | --- | --- |
| 会话 | `display: none` | 看得见 |
| 生图 | 接管中，`z-index: 60` | **被压在下面** |

按钮一直在 DOM 里，位置也正确（实测 `88,11`，28×28），只是中心点命中的是插件自己的
标题行。会话态之所以正常，纯粹因为它的插件视图是隐藏的。

**改法是抬座位，不是降接管层。** `--z-takeover: 60` 在仓库里是钉死的：兄弟面板（任务板、
SSH）都照着这个数写过，挪它会连锁影响插件之外的代码。所以新增一层 `--z-shell-seat`
（63，层级表里独占一个号），只抬这个只在收起态存在的宿主座位。

同时用宿主自己发布的 `--dsh-frame-top-clearance` 给面板加顶部内边距——宿主文档里就是
这么约定的：内容抵达左上角的主面板按它做内边距，免得落在红绿灯或控件底下。

## 标签栏：不再和「新建会话」差 2px

真机（DSH 0.2.1-rc.5）量出来：标签栏 `16..264`，「新建会话」`14..266`，左右各差 2px。

上一版的几何检查是**绿的**，因为 fixture 自己声明了 `--dsh-sidebar-paint-inset: 3px`，
和 CSS 里的 fallback 正好一致——检查在和自己的假设对答案。真宿主整条祖先链上都没有
这个变量，按钮用的是写死的 `margin: 2px`。

所以「跟随宿主同一内缩」这个前提本来就落空，插件一直在用一个凭空 fallback 的 3px。

现在 CSS 不再假装知道内缩是多少，只保留 border-box 和 8px 下间距；`alignToSeat`
直接读兄弟按钮的**已用 margin** 写到标签栏。样式表看不见兄弟的 used value，这是唯一
诚实的来源——宿主改数字也不用同步改插件。放在 `placeTabs` 每次修复时重测，React 重建
按钮后不会留旧值。

真机复测：标签栏与按钮都落在 `14..266`，左右 0 漂移，间距 8px。

## 标签栏：方向键真的能用

`role="tab"` 不只是个属性，它承诺了键盘契约：Tab 键进组一次，组内用方向键切换。

上一个 PR 给两个按钮加了 `role="tab"`，但两个 tab 都在 Tab 序里，方向键什么也不做。
现在复用 `src/client/tablist.ts` 的 `tabIndexFor` / `onTablistKeyDown`，把 `tabIndex`
写进同步选中态的**同一处**，让 `aria-selected` 和 Tab 序永远描述同一个状态。

侧栏入口是命令式构建（不是 React），所以手工绑定键盘而不是靠 `onKeyDown`；点击和方向键
共用同一个 `activate`，避免两条路径悄悄漂移。

## 检查

这一版的四个修复都补了对应的守卫，且都验证过把缺陷植回后检查会变红：

| 修复 | 守卫 | 反向用例注入的缺陷 |
| --- | --- | --- |
| 收起键 | smoke 的 `topStrip` 夹具与可见性断言 | 删掉 chrome 白名单那一行 |
| 展开键 | 契约检查断言规则存在，且其层级高于接管层 | 删掉抬座位的规则 |
| 标签栏对齐 | fixture 从源码抽出并 eval 真实的 `alignToSeat` | `alignToSeat` 退回读不存在的变量 |
| 键盘契约 | 契约扫描覆盖 `.ts` 的 tablist | 去掉 roving tabIndex |

另外真机验收（桌面 app，通过 CDP 量几何）确认了会话态与生图态的 `topStrip` /
`logoRow` / 标签栏几何完全一致，折叠控件在生图态可达。

## 已知边界

- 抬座位这条规则只对 macOS 桌面生效（`[data-platform='darwin']`），Windows 标题栏
  走的是另一条路径，不受影响。
- 宿主的窗口 chrome 座位结构是宿主内部实现。插件只依赖 `data-shell-leading` 这个
  数据属性，以及「收起侧边栏 / 打开侧边栏」这两个可访问名——宿主改文案时需要一起更新
  词表（`SIDEBAR_TOGGLE_LABELS`）。
