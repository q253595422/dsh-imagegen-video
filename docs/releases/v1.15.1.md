# v1.15.1 — 火山适配的收口修复

一句话概括：v1.15.0 把 Seedream / Seedance 接上了方舟的真实契约，这一版修的是「接上之后仍然会在真上游上出问题」的几处细节——像素尺寸越界、能力按渠道别名而非上游 ID 判断、文档里对推理接入点的错误说法，以及代码生成路径在缺渠道时被误拦。

## 为什么

v1.15.0 发布后逐字段复核方舟文档，发现七处会真实影响结果的问题。它们不是风格问题，每一处都会让某类请求在真上游上失败或失真。

## 修了什么

### 生图（Seedream）

- **像素尺寸会越过上限。** 4K、16:9 时按目标总像素解出的 `2866x1612` 四舍五入后是 16,779,264 像素，比 4096² = 16,777,216 多了 2048，上游直接 400。现在改为在目标高度附近扫描偶数高度、挑出「合法且比例最接近」的一对；扫描不到时按 `sqrt(target / (w*h))` 缩放兜底。文档示例同步改成 `2784x1566`。
- **lite / 4.5 的档位下限不同。** 5.0 lite 与 4.5 的文档预算是 `2560x1440` 起，原先统一按 5.0 pro 的 `1280x720` 起算，1K 档会在这些型号上被拒。现在按型号分支。

### 生视频（Seedance）

- **能力判定看的是渠道别名，不是上游 ID。** 渠道可以把 `seedance-hd` 映射到 `doubao-seedance-2-0-fast-260128`，而 720p 上限属于后者。原先引擎和面板都拿别名去判，于是面板会给出 1080P、提交后 400。新增 `resolveVideoModelId`，引擎与面板都先解析出上游 ID 再判能力（`src/video-model-catalog.ts`、`src/video-engine.ts`、`src/client/VideoPanel.tsx`）。
- **分辨率降档会掉到最低档。** `normalizeVideoResolution` 原先回落到档位表第一项，`1080P` 在 fast 型号上会变成 `480P`，等于白白丢掉大半画面。现在取「不超过请求的最高档」，只有低于下限时才向上取。
- **文档对推理接入点的说法不成立。** 之前写成 `ep-…` 也能用。实际上协议族按模型 ID 前缀判断，`ep-…` 识别不出来，生视频会在提交前明确报「协议族未知」。README、预设提示与发布说明已一起改正。

### 代码生成路径

- **`renderer: code` 的提交不再要求渠道。** 代码渲染不需要任何生图/生视频渠道，但两个提交路由仍在校验渠道，缺渠道时会在真正开始渲染之前被拦下（`src/routes.ts`）。
- **代码识别不再用方法白名单。** 原先只有 `ctx.background/rect/roundRect/circle/line/text/gradient` 这几个调用算「代码」，模型如果写了 `ctx.fillRect(...)`（本渲染器没有这个方法），整段会被判成散文并静默换成内置标题卡——真正的问题（方法不存在）反而被藏起来。现在任何 `ctx.<方法>(` 都算代码，交给执行器报 `code-runtime`，错误里带着方法名。被判定为散文时也会引用模型原话的前 160 字，让用户能区分「模型拒绝了」和「模型写错了 API」。

## 验证

- `pnpm run typecheck`、`pnpm run build`、`pnpm test` 全绿。
- `scripts/smoke-video.mjs`：`V1c4` 断言面板按上游 ID 描述能力；`V1c3` 覆盖时长/分辨率收敛；`V6b` 走「别名 `hd`、上游 fast」的完整运行时路径。
- `scripts/smoke.mjs`：`B7b` 覆盖编辑路径的水印与 1K→2K 档位收窄，以及 6 种比例在 4K 下的尺寸扫描。
- `scripts/smoke-code-render.mjs` 增至 16 项，新增两条**反向验证过**的用例：
  - `C4b2`：裸函数体 `ctx.fillRect(...)` → `code-runtime` 且错误信息含 `fillRect`。把修复临时回退后该用例失败（旧代码把它当散文换成标题卡），恢复后通过。
  - `C3b`：散文回答的降级原因里必须引用模型原话。旧代码的失败信息是「没有 render 函数，也没有任何绘制调用」，不含原文。

## 依赖与边界

- 新增依赖：**无**。
- **火山真实端到端仍未在本机跑过**：开发机上没有火山方舟的 API key（凭据里只有 Agnes / Comemoe / TX 等），且 `ark.cn-beijing.volces.com` 不在安全门允许的地址列表里，直接请求会被拦下。当前验证止于「离线假上游 + 方舟官方文档逐字段对照」。若要本机真跑：设置 → 生图配置里加一个火山渠道，地址填 `https://ark.cn-beijing.volces.com/api/v3`，填 Ark key，模型用方舟控制台的 `doubao-seedream-*` / `doubao-seedance-*`。
