# v1.15.0 — 火山方舟：Seedream 生图与 Seedance 生视频按真实协议适配

一句话概括：火山方舟（Volcengine Ark）的 Seedream 生图与 Seedance 生视频不再是「名字看着像就按通用协议发」，而是各按方舟自己的契约整形请求。一个 Ark 渠道同时服务生图与生视频。

## 为什么

之前这两个模型族走的是兜底形状，在真上游上会以不同方式失真：

- **Seedream**：方舟没有 `aspect_ratio` 参数，`size` 只能填档位（`1K`/`1.5K`/`2K`/`3K`/`4K`）或显式 `宽x高`，二者不可混用。原先发的是档位字符串，于是你在面板里选的比例被直接丢掉——选 16:9 出来的仍是接近正方形的图。另外 `watermark` 在方舟**默认 true**，每张图右下角都带「AI生成」。
- **Seedance**：`doubao-seedance-*` 之前被归到通用视频端点，提交到 `/videos`，而方舟的接口在 `/contents/generations/tasks`，请求体形状也完全不同（`content` 数组 + `role`），所以这条路径在真上游上根本走不通。

## 做了什么

### 生图（Seedream / Ark）

- 选了具体比例时，按该模型的**文档像素预算**换算出显式的偶数宽高：

  | 模型族 | 总像素区间 |
  | --- | --- |
  | 5.0 pro / flash | `1280x720` ～ `2048x2048x1.1025` |
  | 5.0 lite、4.5 | `2560x1440` ～ `4096x4096` |
  | 4.0 | `1280x720` ～ `4096x4096` |
  | 3.0 t2i | `512x512` ～ `2048x2048`（只接受像素值） |

  例：5.0 pro、比例 16:9、清晰度 4K → `2866x1612`（比例 1.7779，总像素 4,619,992，在预算内）。
- `auto` 保留档位字符串，这是方舟「让模型自己决定」的合法写法。
- 每次显式发送 `watermark: false`（文生图与图生图都一样）。
- 响应格式：方舟用 `response_format: 'url'` 并回源下载；网关形态的 Seedream 仍用 `b64_json`。

### 生视频（Seedance / Ark）

- 新增 `seedance` 协议族：提交 `POST /contents/generations/tasks`，轮询 `GET /contents/generations/tasks/{id}`。
- 请求体：

  ```json
  {
    "model": "doubao-seedance-2-0-260128",
    "content": [
      { "type": "text", "text": "…" },
      { "type": "image_url", "image_url": { "url": "data:image/png;base64,…" }, "role": "first_frame" }
    ],
    "ratio": "9:16",
    "resolution": "1080p",
    "duration": 5,
    "watermark": false,
    "generate_audio": false
  }
  ```

  - 首尾帧模式发 `first_frame` / `last_frame`；参考图模式逐张发 `reference_image`（2.x 支持）；图生视频发单张 `first_frame`。
  - 比例字段是 `ratio`；分辨率小写；时长是整数秒。
- 轮询结果从 `content.video_url` 取成片，`content.last_frame_url` 作为封面回落，`duration` 作为真实时长。
- **收敛而不是硬发**：2.x 时长窗口 4–15 秒，1.0 为 2–12 秒；`fast` / `mini` 上游最高 720p；1.0 不支持 `reference_image` 角色，`1.0 pro fast` 也没有尾帧，所以这些模式会从对应型号上收起来。越界的请求会被收进窗口，并把分辨率降到该型号真正支持的最高档（1080P 在 fast 型号上降为 720p，而不是掉到 480p）。
- `watermark` 生图默认 true、生视频默认 false，插件一律显式发送 `false`；`generate_audio`（2.x 才有，默认 true）显式发 `false`，1.0 系列不带这个字段。

### 渠道预设

`volc-ark-seedream` 改名为「字节 · 火山方舟（Seedream / Seedance）」，图片模型换成方舟控制台的真实 ID，并新增视频模型目录：

- `doubao-seedream-5-0-pro-260628` / `-5-0-260128` / `-4-5-251128` / `-4-0-250828`（保留旧的 `seedream-5.0-pro` / `seedream-4.0` 别名兼容）
- `doubao-seedance-2-0-260128` / `doubao-seedance-2-0-fast-260128` / `doubao-seedance-1-0-pro-250528`

模型 ID 请填方舟控制台的 `doubao-seedream-*` / `doubao-seedance-*`：协议族按这个 id 前缀判断，推理接入点（`ep-…`）识别不出协议族，生视频会在提交前明确报「协议族未知」而不是静默发出一个形状错误的请求。

## 验证

- `pnpm run typecheck`、`pnpm run build`、`pnpm test` 全绿（含 UI 契约检查）。
- `scripts/smoke.mjs` 的 `B7`：断言 Ark 的 `size` 是 `宽x高`、比例保持在 16:9、宽高为偶数、总像素落在 5.0 pro 的预算内，且 `watermark === false`、`response_format === 'url'`、不出现 `resolution` 字段。
- `scripts/smoke-video.mjs` 新增两项：
  - `V1c2`：Seedance 提交体是 `content[{text}] + content[{image_url, role:'first_frame'|'last_frame'}]`，带 `ratio`、小写 `resolution`、整数 `duration`、`watermark:false`、`generate_audio:false`；轮询打到 `/v1/contents/generations/tasks/{id}` 并由 `content.video_url` 取到成片。
  - `V1c3`：fast 型号请求 `1080P` / 30 秒 → `720p` / 15 秒；1.0 pro 请求 1 秒 → 2 秒、`1080p` 保留。

## 依赖与边界

- 新增依赖：**无**。
- 仍只支持方舟文档化的字段；未文档化的参数（如 1.0 上的多图参考）不发送，面板也会把不支持的选项收起来。
- 时长仍由面板的 5 / 10 秒两档控制（两者都落在所有 Seedance 型号的窗口内）；通过 Agent 调用可以传入别的秒数，会被收进对应型号的区间。
- 收敛后的值会写进请求，但**不会改写你在面板里选的原值**：同一次生成之外，选择保持原样。
