# v1.15.2 — 视频取片支持 `/content` 回退

一句话概括：任务已经渲染完成、轮询却因为没有 URL 被判失败的情况，现在会真的把成片取回来。

## 为什么

`readPoll()` 只在轮询响应体的六个字段里找视频地址，找不到就把任务判成失败，弹出「视频任务已完成但未返回视频地址」。

但 OpenAI 官方的视频 API——以及照抄它的 OpenAI 兼容网关——在终态里**不返回任何 URL**：`status` 走到 `completed`，成片只通过 `GET /v1/videos/{id}/content` 以二进制流提供。于是上游明明渲染好了，插件这边报失败，用户拿不到片子；对按次计费的上游来说，这次调用是白花的。

这不是某一个网关的私有行为，所以修在上游协议这一层，而不是给某个渠道加特判。

## 做了什么

- **轮询结果能表达两种取片来源**：响应体里有 URL 就照旧用 URL（优先级不变，它通常指向 CDN，比回源更省事）；没有任何 URL 但状态已完成时，轮询把 `/content` 端点作为片源返回，而不是判失败。
- **下载沿用同一条腿**：`/content` 的字节走原有的下载函数，同源鉴权转发、MIME 推断、体积上限全部照旧生效——没有为它新开一条绕过这些约束的通道。
- **失败仍然是失败**：`/content` 返回 404 之类的错误时，报的是下载环节的真实错误，不会静默当作成功。任务真失败（`failed` / `expired`）的判定也完全没变。

## 验证

- `scripts/smoke-video.mjs` 新增两条用例：一条让 mock 上游只给 `/content`、响应体不含 URL，断言成片被取回；一条让 `/content` 返回 404，断言报出的是下载错误而不是「已完成但无地址」。
- `scripts/verify-negative.mjs` 加了对应的缺陷注入：把回退移除后，新用例会变红，确认这两条测试确实在看这件事。
- `node scripts/smoke-video.mjs` 全绿。

## 同一版本里的界面修复

这一版还带上一批真浏览器逐项复核过的界面问题（八个模块）。它们与视频链路无关，但同样进 1.15.2 的包，所以记在这里：

- **被完全盖住的画布节点现在有提示。** 把节点拖到另一个节点正下方，原来屏幕上什么都不剩、也没有可点的目标。现在两个节点会互相描边，被盖的那个带一个 `role="status"` 徽标，写明压在它上面的是谁。提示**松手后仍保留**——那正是节点还看不见的时候。节点分开后自动消失。
- **错误色此前全是死引用。** `--dsw-alias-label-error` / `-warning` 在 dsh 主题里根本没有定义，六十处声明一直在静默回退到继承色，包括上面那个徽标（白字配透明底）。现在统一用实测能解析的 `--dsw-alias-state-error-primary` / `-state-warn-primary`。
- **电商分区标题莫名折行。** 标题是 flex 行里的裸文本节点，被旁边的提示挤到 69px，而五个字要 70px。标题改为不收缩、提示补 `min-width: 0`，顺带让原本失效的 `text-overflow: ellipsis` 真正生效。**栏宽没有改动**。
- **看起来成功的失败。** 保存设置、测试渠道、检查更新、清空诊断，现在都会说明到底发生了什么，并保留上游给出的原因而不是一句通用文案；连接测试失败不会再显示成通过。
- **弹窗与下拉键盘可用了。** 焦点会被困在弹窗内并在关闭时归还；下拉具备 combobox 语义、`aria-activedescendant`、首字母跳转与方向键导航；快捷键说明成为真正可聚焦的对话框。
- **PPT 配置步骤能看出进行到哪一步。** 每一步各自报告状态，运行状态显示在产生它的控件旁边；提示框随内容增长而不是被裁掉。

配套的契约检查：冒烟套件断言重叠徽标会出现、松手后保留、节点分开后清除；UI 契约检查断言分区标题不收缩、提示的省略号能解析。

## 影响面

视频修复只影响「轮询响应体里没有视频地址」的分支；有 URL 的渠道走的是原来那条路径，行为不变。界面部分不改变任何接口与数据格式。

Closes #9.
