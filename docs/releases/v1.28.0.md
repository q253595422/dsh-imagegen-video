# v1.28.0 — 插件拆成 13 个可独立装卸的组件；画布可整图导出/导入；Agent 能读写画布结构

本版的主体是**结构**：宿主侧从一个组件拆成 13 个可各自启停的 Cordis 组件，无限画布补上整图搬运与 Agent 读写能力，画布工作流执行器补上续跑、强制重跑与并发闸门。同时修掉手机端第三轮走查发现的版式问题，以及几处「切走再回来就丢东西」的画布缺陷。

## 组件拆分：宿主插件行从 1 个变成 13 个

在 DSH 的插件管理里，本插件此前只表现为**一行**（`@q253595422/dsh-imagegen-video`），所有功能共享同一个宿主 fiber——任何一个 feature 需要重启，其余全部连坐。现在拆成 1 个共享核心 + 12 个独立 feature 组件：

| 组件 | 职责 |
| --- | --- |
| `imagegen` | 共享设置、渠道、队列、订阅、更新检查与浏览器工作台 |
| `imagegen-image` | 生图、任务与历史、图片工具与编辑指令 |
| `imagegen-video` | 生视频、导演层、任务与历史、代码渲染探测与视频工具 |
| `imagegen-canvas` | 画布文档、素材、文件、图层与画布工具 |
| `imagegen-gallery` | 素材库与模型资产 |
| `imagegen-templates` | 模板、收藏与定时刷新 |
| `imagegen-skills` | 画布技能、技能库与宿主技能/Agent 绑定 |
| `imagegen-ppt` | 图片转可编辑 PPT |
| `imagegen-ecommerce` | 商品链接解析与详情页文案 |
| `imagegen-outfit` | 服饰穿戴参考图 |
| `imagegen-prompt` | 提示词增强 |
| `imagegen-storage` | 对象存储与自动上传钩子 |
| `imagegen-diagnostics` | 诊断与反馈信号 |

- 每个组件有自己的 exports 子路径（如 `@q253595422/dsh-imagegen-video/video`）、自己的多语言文件与自己的注册行，可以单独 mount 与 unload。
- 路由归属由一处判定函数统一决定，未知端点留在核心；卸载某个 feature 只摘掉它注册的路由、工具、命令与后台钩子。
- 移除核心会连带挂起所有依赖它的组件。
- **边界要说清**：这些都是生命周期边界，不是权限边界。浏览器侧仍是**一个共享工作台**（当前宿主只从包根发现浏览器包），所以关掉某个 feature 后仍可能看到它的入口；内部工作流也可能调用共享能力（例如画布技能发起生成）。已经提交到上游的任务不会因为卸载组件而被取消，记录也不会被删除。
- 老安装要看到这 13 行，需要重新加载新版包并重组它的 bundle；只构建本仓库不会替换桌面宿主里另行安装的那一份。

## 画布：整图导出 / 导入

导出一个 JSON 文件即可搬走整张画布：v2 文档 + 全部被引用素材的字节内联 base64。**不引入 zip 依赖**，出问题时可以直接用文本工具打开看。

- 导入**永远是新建**：拿新 id，节点 id 原样保留（连线与分镜靠它），绝不覆盖已有画布。
- 拿不到字节的引用不静默丢弃：逐条返回 `unresolved` 并带上 nodeId（磁盘已删的素材、按 `docs/parity-contract.md` 1.7 节只引用不复制的视频 clip），界面能直接指到坏图。
- 单份 bundle 上限 256MB（解码后）；超限、坏 base64、路径穿越、文档版本高于本插件能读的，全部在写入前逐个拒绝。
- **界面上还没有导出/导入的按钮**。这一版交付的是宿主侧两条路由（`/canvas/bundle/export`、`/canvas/bundle/import`）与全部校验，界面入口留到下一版；目前只能通过路由直接调用。

## 画布：Agent 能读画布、建节点与连线

新增八个 Agent 工具：`list_canvases`、`read_canvas`、`create_canvas`、`add_canvas_node`、`update_canvas_node`、`remove_canvas_node`、`connect_canvas_nodes`、`disconnect_canvas_nodes`。

- **没有任何 run/generate 类工具，也不会加**。生成要用户自己在画布上按运行键——能自主花钱的 Agent 是事故不是功能。这条被写成了断言：套件里有一条用例扫描全部画布工具的名字与 schema，加进一个生成工具立刻变红。
- 写操作一律走 `CanvasStore.save(document, 读到的 revision)`，与画布窗口同一把乐观锁；冲突时返回可操作的说明，而不是覆盖用户刚做的编辑。
- `read_canvas` 附带一句结构提示（没有下游连接的节点、孤立节点），让模型能自己发现「这张图跑不出东西」，而不是把图原样丢回去。

## 画布工作流：续跑、强制重跑、层内并发闸门

执行器的三项能力全部是加法，现有签名与默认行为不变：

- **续跑**：上一轮已有结论的节点不再提交，按 `cached` 计。画布上的「运行工作流」一直在用这条路径——有产物的节点直接算有结论。
- **强制重跑**：指定节点**及其下游闭包**以 force 提交，并优先于续跑。只重跑节点本身会让下游拿到旧产物，把一次修改报成「没变化」。
- **层内并发上限**：默认不限（整层一起提交，与以前一致）；可以限制同层最多同时发几个，比如一层二十个图节点、只想同时发三个。
- **这两项目前没有界面开关**：画布只传了流程本身，`rerun` 与 `maxParallel` 还是执行器层的能力，等界面接上。

## 其它修复

- **切走画布不再丢弃在途技能运行。** 以前切到别的画布会整体重建运行表，只留下「属于这个画布且没挂起」的条目——结果是在跑的 run 被丢掉，已经挂起等落地的输出也被丢掉，而轮询会跳过挂起项，那是它唯一的一份拷贝。
- **技能挂起输出的落地按 id 集合触发**，不再看条目数量。一次提交里删掉一条、同时新增一条时长度不变，effect 不重跑，新来的那条永远不落地。
- **技能轮询加防重入。** host 慢的时候上一次 tick 还在等网络，下一次就起来了：两条 tick 读同一份状态，重复请求并各弹一次通知。
- **画布导入失败区分「文件太大」与「不是画布文件」。** 以前两者都报成「超过 256MB」，一个被截断的 2KB 文件会被告知去查容量问题。
- 删掉一段没有任何读者的连线派生代码（真正画连线的是另一处，同一套过滤规则已经漂移过一次）。

## 仓库侧

- 收录扫描的四项缺失补齐（`SECURITY.md`、Dependabot 配置、三个工作流的 action 全部固定到提交 SHA），第三方插件目录的扫描门槛已通过。
- **发布流程加闸门**：版本号已发布且 tag 指向别的提交时，release 直接失败并说明怎么 bump，而不是静默替换已发布版本的资产；同时补上 release 侧的无头浏览器安装（此前 release 跑界面守卫必红，而 CI 是绿的）。
- CI 里四个浏览器守卫此前一直「找不到浏览器 → 跳过 → 退出 0」，现在缺浏览器在 CI 下按失败处理，本地才跳过。
- 反向验证可以并排跑：14 个轻量组 `--jobs 3` 实测全过（`contracts` 单组 577s，占串行总时 93%——瓶颈是单组内的工作量，不是调度）。
