# v1.17.1 — 导航不重影、侧栏换座不丢、上限不再自相矛盾

一句话概括：1.17.0 之后报上来的四处界面缺陷，包括一处会重复扣费的提交缺陷，在这一版修掉；全部改动都在界面层，没有动生成链路。

## 为什么

1.17.0 把导航从 6 项扩到 9 项，同时把三个工作区重排了一遍。这两件事各自都对，撞在一起暴露了三个问题：导航行的内容宽度越过了容器宽度，而定位代码把视口坐标当容器坐标用；侧栏切换器假定「新建会话」按钮一定在，别的插件抢走侧栏之后它就不在了；重排把两个表单的提交按钮从 `type="button"` 改成了 `type="submit"`，但 `onClick` 忘了删。

第三个最贵：一次点击会走两条路径，`generate()` 被调用两次，用户被扣两次费。

## 做了什么

### 导航：A+ 详情页不再出现两个标题

- **根因**：`GooeyNav` 的 `updateEffectPosition` 用 `getBoundingClientRect()` 取 tab 位置（视口坐标），却用来给一个 `overflow-x: auto` 容器里的子元素设 `left`（容器坐标）。行不溢出时两者相等，一旦容器横向滚动，装饰层和滑块就整体偏移一个 `scrollLeft`，看上去像是每项都多印了一份。
- **修法**：算 `left`/`top` 时把 `container.scrollLeft`/`scrollTop` 加回去，把视口坐标换算成容器坐标。
- 只在窄于 ~1280px（导航行真的溢出）时才复现，所以在宽窗口上一直没人看见。

### 侧栏：别的插件抢走侧栏时，切换器换座而不是消失

- `seatOf()` 过去用 `querySelector` 取第一个锚点。桌面外壳会先渲染一份 `display: none` 的移动端副本，于是取到的常常是没有盒子、也没人看得见的那个。
- 现在按文档顺序遍历，取第一个**真的在画**的锚点；`isVisible()` 会一路向上检查到 `body`，自己或任一祖先 `display: none` 就跳过。`sidebarRoot()` 与「新建会话」按钮的查找都用同一条规则。
- 「新建会话」行被隐藏时，切换器退到栏首，并靠 `data-dsh-imagegen-tabs-seat='top'` 补上一点间距。

### 上限：空表单不再写着「参考图上限 0 张」

- `referenceCapacity()` 原先只返回 `usable`，而 `usable` 同时取决于上限和已选数量——表单空着时它就是 0。界面拿它当「上限」显示，于是出现一句自相矛盾的话。
- 现在多返回一个 `limit`（单纯的上限），空表单显示 `limit`，已选时仍显示 `usable`；提交栏在没选图时也有自己的文案，而不是「本次会带上 0 张」。

### 提交：一次点击只生成一次

- 「服饰穿戴」与「带货图文」的提交按钮同时带着 `type="submit"` 和指向同一处理函数的 `onClick`。表单提交和点击各触发一次，一次点击发出两个 `/generate` 请求、扣两次费。去掉多余的 `onClick`，只留表单提交这一条路径。

### 重排后的表单形态

- 服饰穿戴、带货图文改用分区表单：字段分组带标题与说明，「服饰穿戴」按服装 / 模特 / 场景分区，「带货图文」按链接 / 商品 / 平台分区。
- 带货图文的平台选择从 `<select>` 换成四个 pill——`<select>` 的当前值在打开前看不见。四个值与标签不变，`promoImagePrompt` 收到的输入不变。
- 生成的文案落进可编辑的输入框：标题、正文在生成之后仍能改，复制按钮复制屏幕上的内容，不是模型返回的原文。
- 三个工作区在 0 宽、极窄、超宽下都不再被压成一条。空态文案改用自己的键，不再借用「生成结果 1」这类看起来像已有结果的字符串。
