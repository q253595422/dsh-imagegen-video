# v1.7.8

一个打包归属修正，没有行为变化。它属于「安装一次就能看出差别」的那类改动：
装 1.7.7 会多拉一份宿主已经提供的包，装 1.7.8 不会。

## 改了什么

**`@deepseek-ai/schemastery` 从 `dependencies` 移到 `peerDependencies`。**

它不是本插件的实现细节——它的 `z` 构建的是**宿主拿去校验**的配置 schema，
所以必须用宿主那一份。把它声明成依赖，等于每次安装都在宿主的副本旁边再拉
一份 `@deepseek-ai/*`，既是错误的归属关系，也正是插件目录收录规则里点名
禁止的事。

`devDependencies` 仍然保留它，本地的构建、`tsc --noEmit` 与整套离线检查
解析路径与之前完全一致；变的只有发布出去的清单。

## 为什么要单独发一版

1.7.7 已经从 npm 装出去了，它的清单里 `schemastery` 仍在 `dependencies`。
registry 上的版本不可改写，所以这个修正只能体现为新版本，不能声称它对
1.7.7 也成立。

## 验证

- `pnpm run typecheck`、`pnpm test`（十一项离线检查）、`pnpm run test:negative`
  全绿；版本号两处（`package.json` 与 `src/protocol.ts` 的 `PLUGIN_VERSION`）
  由 `smoke.mjs` 断言一致。
- 打包后装入隔离的 `DSH_HOME`：profile 解析到宿主自带的 schemastery，
  `lib/index.js` 正常导入。
- 本版同时用来验证一件事：`release.yml` 里那个默认关闭的 npm job，在配好
  Trusted Publisher、并把仓库变量 `NPM_PUBLISH` 设为 `true` 之后，能否只靠
  GitHub OIDC 把包发出去——不依赖任何存在本机的 npm token。

## 已知边界

- 这一版**没有**用户可见的功能变化。如果你已经装好 1.7.7 且不在意多一份
  schemastery，可以跳过。
- 首次发布（1.7.7）走的是人工流程：npm 的 trusted publishing 只能挂在已存在
  的包上。从 1.7.8 起才由 CI 发布。
