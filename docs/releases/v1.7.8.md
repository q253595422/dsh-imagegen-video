# v1.7.8

一个打包归属修正，没有行为变化。它属于「安装一次就能看出差别」的那类改动：
装 1.7.7 会多拉一份宿主已经提供的包，装 1.7.8 不会。

## 改了什么

**`@deepseek-ai/schemastery` 从 `dependencies` 移到 `peerDependencies`。**

它不是本插件的实现细节——它的 `z` 构建的是**宿主拿去校验**的配置 schema，
所以必须用宿主那一份。把它声明成依赖，等于每次安装都在宿主的副本旁边再拉
一份 `@deepseek-ai/*`，既是错误的归属关系，也正是插件目录收录规则里点名
禁止的事。

`devDependencies` 仍然保留它，本地的构建、`tsc --noEmit` 与整套离线检查
解析路径与之前完全一致；变的只有发布出去的清单。

## 为什么要单独发一版

1.7.7 已经从 npm 装出去了，它的清单里 `schemastery` 仍在 `dependencies`。
registry 上的版本不可改写，所以这个修正只能体现为新版本，不能声称它对
1.7.7 也成立。

## 验证

- `pnpm run typecheck`、`pnpm test`（十一项离线检查）、`pnpm run test:negative`
  全绿；版本号两处（`package.json` 与 `src/protocol.ts` 的 `PLUGIN_VERSION`）
  由 `smoke.mjs` 断言一致。
- 打包后装入隔离的 `DSH_HOME`：只拉两个包（插件 + `lucide-react`），
  profile 下没有 `schemastery` 副本，宿主自带的 3.18.4 被解析，
  `lib/index.js` 正常导入（132 个导出，`CURRENT_VERSION` 1.7.8）。
- 本版也是**第一次由 CI 发布**：没有任何 npm token，走 GitHub OIDC，
  并附带 Sigstore provenance 签名（可在 npm 页面看到「Built and signed on
  GitHub Actions」）。

## 一个被修掉的假失败

这一版的 CI 第一次跑是红的，而它其实是发布成功的：npm 打印了
`+ @q253595422/dsh-imagegen-video@1.7.8` 和 provenance，但 registry 的**读**
路径直到 3 分 16 秒后才能看到这个版本，而当时回读窗口只有 60 秒。

发布任务的回读窗口改成 5 分钟；窗口耗尽时的报错也分成两种说法——「我们发布
了、npm 退出码 0」与「这次运行没发布过」——因为原来的措辞会把一次成功的发布
指向凭据问题。`verify-pack.mjs` 现在断言这个窗口必须大于 4 分钟（阈值旁边写着
3 分 16 秒这个实测值），反向套件用 6×10s 的旧循环证明这条断言会变红。

## 已知边界

- 这一版**没有**用户可见的功能变化。如果你已经装好 1.7.7 且不在意多一份
  schemastery，可以跳过。
- 首次发布（1.7.7）走的是人工流程：npm 的 trusted publishing 只能挂在已存在
  的包上。从 1.7.8 起才由 CI 发布。
- 1.7.7 与 1.7.8 之间没有功能差异，**只有包清单的归属关系不同**。
