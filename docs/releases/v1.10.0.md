# v1.10.0 · 分镜：一列镜头，各出一段视频

> 各版本改动见 [CHANGELOG.md](../../CHANGELOG.md)。

本版在无限画布上加了一个**分镜节点**，并把「上一镜接着下一镜」做成画布上的一等操作。
它没有另起一套工作流：每一镜的成品就是一个普通的视频节点，预览、下载、收藏、重试和拼接
都还是原来那条链路。

## 分镜

- **一个节点就是一列镜头。** 每镜一条提示词、一个时长，可以加、删、上下移动；列表顺序
  就是片序。「每镜独立」一次把还没有视频的镜头全部提交；「接上一镜尾帧」一次跑一镜，
  用上一镜的最后一帧当这一镜的第一帧，镜头之间才真正接得上。
- **接不上的时候会说出来。** 选了「接上一镜尾帧」而上一镜还没出片时，这一镜的生成按钮
  是禁用的，不会提交一个悄悄退化成纯文本生成的请求。
- **每一镜的状态来自它自己的视频节点。** 已完成、生成中、失败、还没生成四种状态都读自
  那张节点，所以分镜上看到的进度和画布上看到的片段永远一致；删掉片段，那一镜就回到
  待生成，可以直接重来。

## 拼接

- **分镜自己会拼。** 有两镜及以上出片后，「拼接全部镜头」把它们按镜头顺序交给现有的
  compose 链路——同一张 ①②③ 顺序确认卡、同一个本机 ffmpeg。还在生成的镜头不会被塞进
  去，界面会说明少了几镜，而不是提交一次注定失败的拼接。

## 画布

- **取尾帧续拍。** 任意已完成的片段都可以一键取结尾帧：生成一张图片节点，并接好一个
  新的视频配置节点，直接写下一镜的描述就能接着拍。这是分镜衔接的手动版，用的还是画布
  上原有的抓帧与生成。
- **刷新不丢。** 镜头列表、画布共享的画幅与分辨率、每一镜和它片段节点的对应关系都存在
  画布文档里；重开画布照旧。文档里存了无法兑现的镜头数据时，保存会明确失败，而不是写进
  去一份半坏的文档。
- **编辑走文档。** 在分镜里改提示词、调顺序，和其他节点一样支持撤销、重做与自动保存。

## 已知边界

- 分镜的镜头数上限为 40。超过上限的文档会被拒绝保存。
- 「接上一镜尾帧」依赖浏览器能解码上一镜的结尾帧；片段文件被清理掉时无法续拍，会给出
  明确提示。
- 分镜不生成配乐、字幕或转场，只负责把镜头跑出来并拼成一条片子。
