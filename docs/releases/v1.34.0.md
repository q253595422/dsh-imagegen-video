# v1.34.0 — 分镜板的「体检」：写之前就知道哪一镜会翻车

> 起点是别人一篇讲创作工作台的文章。真去把那个插件拆开看，能做进我们这里的只有一件事：**在把提示词送进生成之前，就说出哪一镜大概率会出问题**。他们的做法是五份 markdown 加 2600 行 Python 跨文档校验；我们只有一块分镜板，所以只留能从分镜本身算出来的部分，直接长在板上。

## 这块板原来不会说话

分镜板已经在做的事：每镜一条提示词 + 时长、两种衔接（每镜独立 / 接上一镜尾帧）、拼接成片。但它对**写得好不好**一句话都不说。

结果是有几类错误只能在成片里被发现：

- 板设成「接上一镜尾帧」，从第 2 镜起两个参考图槽位都花在接缝上，`submitShot` 里 `plan.castSlots === 0` 是真的不带图。提示词却还写着「阿禾推门进来」——前面几镜有她的脸，后面全没有，脸开始飘。等你看出来，钱已经花了。
- 提示词按秒分了段，加起来 9 秒，这一镜只给了 6 秒。尾巴被截掉。
- 同一段里既写「固定机位」又写「缓慢推近」。上一版并没有把这类矛盾当成错误——它只是让模型自己去理解，而模型会随机选一边。

## 七条规则

全部在 `src/client/storyboard-lint.ts`，纯函数：不读状态、不改文档、不碰网络。

| 规则 | 级别 | 说什么 |
|---|---|---|
| `castMentionedButDropped` | **block** | 提示词写到了钉住的身份，但这一镜不会带它的参考图 |
| `segmentTotal` | warn | 标秒分段合计比镜长长（尾巴被截）或短（模型自己填） |
| `segmentCoverage` | warn | 分段没从 0:00 开始，或起止写反了 |
| `motionConflict` | warn | 同一段里同时写了固定机位和移动运镜 |
| `castOverflow` | warn | 钉住的参考超过上限，后面的永远送不进去 |
| `castDuplicate` | warn | 同名钉了不止一次，只有第一张会送 |
| `shotProblem`（既有） | — | 空提示词 / 时长非法，仍由原路径处理 |

**`block` 与 `warn` 在行为上没有区别**，差的只是颜色。这是有意的：4.5 字/秒这类经验值会误伤（一句无声的动作描述根本不需要那么多时间），把好默认变成一堵墙，比不提醒更糟。这一层只提醒，不阻止任何运行。

## 界面上

- 板顶部一行可折叠摘要，**只在真有问题时出现**。「检查通过」常驻会变成墙纸，用户三天就学会无视整行。
- 展开后逐条列出，每条前面带镜号。
- 有问题的镜头行上多一粒带数字的角标，悬停看全文。一镜可能同时有几条结论，只画一个点用户不知道要改几处。

截图（真实构建产物渲染，非手绘）：

```
体检：1 镜有问题  收起
 1  标秒分段合计 9 秒，比这一镜的 6 秒长，尾巴会被截掉
 1  同一段里同时写了固定机位和移动运镜（1 段），同一秒里镜头不能既不动又动
```

## 两处刻意没做

**不做跨文件契约校验。** 他们那套的价值在于把自己五份文档的编号对得上；我们没有那五份文档，硬造一套只会变成没人读的规则文件。

**不融他们另外三个工作台**（短剧 / 互动游戏 / 视频解说），也不融 GROUP 合生与音色槽位——那些要新引擎或新后端，会把插件变成另一个产品。

## 两条防退化的细节

**标秒正则必须是工厂函数，不能是共享常量。** 带 `g` 的正则是**有状态的**：`test()` 成功一次就把 `lastIndex` 留在末尾，紧接着的 `matchAll()` 从那开始扫，整镜的分段一条都读不出来。更糟的是它只在特定调用顺序下现形——体检静默少报，而每次单独看都正常。

这个问题在开发中真的出现过一次：最早写的是共享常量 + 手动重置 `lastIndex`，看着对，但 `shotHasSegments` 里那次 `test()` 仍会污染下一次 `shotSegments()`。改成每次调用新建正则之后，这类跨调用状态才彻底不存在。反向用例把这处改回共享常量，`L3` 必须变红。

**体检文案不以数字开头。** 第一版写的是「{count} 个分段里同时写了……」，渲染出来是：

```
 1  1 个分段里同时写了固定机位和移动运镜
```

清单每行前面已经有一个镜号，正文再以裸数字开头就是两个数字贴在一起，分不清哪个是镜号。改成把数量放进括号后，`L24`（三语一起查）当场又抓出了 en / ru 里同样的问题——`lintCastOverflow` 在英文里是 `{count} identity references are pinned; …`。
