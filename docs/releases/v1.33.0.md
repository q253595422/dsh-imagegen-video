# v1.33.0 — 导演台换成真 3D + 时间轴；画布补上层级、锁定隐藏、套图、找节点、体检与目录

> **版本说明**：本版把 `v1.32.0` 的导演台从「一张静态构图」升成「一段能播的镜头」：视口换成 three.js 真三维，底部加时间轴与关键帧，顶栏加「导出视频」——导出的 mp4 是一个普通视频节点，下游零改动。同一版里画布也补齐了叠放顺序、锁定 / 隐藏、套图、找节点、体检、整理、对齐条、历史面板与全部功能目录。

## 之前是什么样

`v1.32.0` 的导演台已经能在一个场景里摆多个角色、多台机位，但它是**一张静态构图**：视口是手写的 2D 画家算法——把骨架投影到屏幕、用 metaball 球拼人形、逐球排序。两件事它做不到：

1. **遮挡**。画家算法只对互不重叠的凸体成立。一个立方体摆在人前面时，它挡不住人，只会被人盖住。
2. **时间**。没有时间轴，也就没有「从 0 秒走到 6 秒」这种镜头。

画布那一侧是另一类缺口：卡片的叠放顺序由「谁先被创建」决定，用户看不见也改不了；锁不住 Delete 的「锁定」不存在；一张配置卡只能挂一句话，想一次出三视图得建三张卡；画布大了只能缩到 10% 自己找；跑不起来的图要改一处、跑一次才知道下一处。

## 现在

### 真 3D

视口换成了 three.js 的深度缓冲。截图里的区别不是「更精致」，而是**能被挡住**：立方体摆在人偶前面，人偶只剩头肩。

- 人偶是**放样出来的人体**，不是关节球串。每一段（骨盆、腹胸、颈、头、大臂、小臂、大腿、小腿、手、脚）都是一串椭圆截面的放样面：胸腔左右宽、前后薄，小腿肚后厚前薄，大腿上粗下细。原来那版是「每个关节一颗球 + 每根骨一根等粗圆柱」——横截面永远是圆，于是躯干是一根管子、大臂是一根管子，远看是一个球关节木偶、近看是几根香肠叠在一起。
- 肩、肘、膝、胯、踝保留外露的小球。这是**刻意的造型**（木偶人偶本来就这样），也补上两段放样弯到极限时的缝。
- 头按 7 头身定尺寸：头高 0.204、头宽 0.15。这条走错过两次——第一版只把放样画到 `t=1`（= 颈到头的 0.100），得到一块 0.10 高、0.19 宽的**扁碟**；第二版撑到 `t=2.2` 又过头，成了 0.305 高，正面只显得「头大」，侧面是一颗向后歪的大鸡蛋（5.5 头身）。现在由 `H11` 断言守住 6.5–8.2 头身。
- 导演视角自由环绕（拖拽 / 滚轮 / 重置），机位视角透过 `cameraId` 那台机位看。
- 角色名标签用 canvas 纹理贴成始终面向相机的 sprite，受 `scene.labels` 开关控制。这条是 2D→3D 时漏掉的能力：2D 版一直画标签，3D 版不画，于是切过去之后画面上看不出谁是谁。
- **没有 WebGL 的机器自动退回 2D**，不报错、不白屏（老 GPU、远程桌面、策略禁用）。
- **木偶的样子主要来自材质与光，不是造型精度**。原来只有 `AmbientLight 1.15` + 一盏平行光、没有阴影——环境光开到 1.15 等于把形体全抹平，不管放样多准都会像一张剪贴画。现在环境光压到 0.22，加一盏半球光给上下渐变，主光开投影（`PCFSoftShadowMap`，阴影相机覆盖整个舞台），再补一盏冷色背光把剪影从背景里剥离；木身与关节分成两档颜色（`#d9b483` 浅木 / `#a7814f` 胡桃），浅木身配深关节才是木制人偶的辨认特征。2D 回退渲染器里那三个硬编码的 `0xc8/0xcc/0xd6` 一并改成同一个木色，否则没有 WebGL 的机器上是灰人、有 WebGL 的是木偶。
- 找过现成模型，**没有能换的**：唯一 CC0 且能直接下载的木偶只有 6 个网格、838 面，肘和膝都不能弯（换掉等于把 11 段姿势系统砍回刚体）；拓扑最贴合的 kernelCAD 那个 CC0 木偶只有「Open in Studio」没有直链；three.js 的 `Xbot/Michelle/Soldier` 是 Mixamo 派生、不能随包分发；`boytchev/mannequin.js` 是 GPL-3.0，塞进 Apache-2.0 会让整个分发变成 GPL。
- **视口拖动/滚轮/重置一度全是死的**（2026-11-18 实机发现）：面板把拖动写进自己的 `view` state，而那份 state **没有任何消费方**——3D 场景的 `orbit()` / `zoom()` / `resetView()` 三个方法都写好了，却一个调用方都没有。更隐蔽的是即使调用了也不会动：这三个方法只改 `orbitState`，而真正出帧的是 `render(stage)`，由面板的 effect 驱动，依赖里没有相机。现在 `StageViewRenderer` 增加了三个可选转发方法，场景在相机变化后自己重画一帧。`stage-preview-shot.mjs` 里补了一条**逐字节对比拖动前后画布**的断言——这条路径以前一条检查都没有，所以测试全绿而用户拖不动。
- 「生成参考图」也走 3D：视口里是 three 渲染的人形，导出却用 2D 画家算法画一遍的话，用户拿到的是一张和眼前完全不同的图。导出必须是「你看到的那一帧」，渲染不出来才退回 2D。

### 时间轴

底部一条时间轴：播放 / 暂停 / 逐帧 / 循环、时长 2–15 秒、拖动 scrub、逐轨关键帧菱形。

- **固定 30fps，时间以「秒」存**。帧号是渲染期派生量，不是存储格式——存帧号会在改时长时全部错位。
- **关键帧所有字段可选**（`rig?` / `position?` / `facing?` / `camera?`）。同一时刻「转身」和「摆姿势」是一条关键帧，不是两条。
- **整份时间轴存在 `stage.timeline` 里**，不分散到 actor / camera 上。删掉一个角色时轨道跟着消失，不会留下孤儿轨道。
- **运动轨迹在活动区间内覆盖位置关键帧**，而不是像牧野那样直接报 `motionPathsCannotCoexistWithPositionKeyframes`。轨迹段在轨道上画成琥珀色横条：一段区间用横条、一个时刻用菱形。

### 导出视频

顶栏「导出视频」逐帧渲染 → 逐帧上传 → 宿主用 ffmpeg 编成 mp4，落成一个普通视频节点并与导演台连线。

**编码不在浏览器里做。** 牧野用 WebCodecs，代价是它自己得给用户看一句「当前浏览器不支持此画幅的 H.264 编码」。这个插件的宿主本来就有 ffmpeg（`src/clip-compose.ts` 已在用），把编码放到宿主之后画幅不受编码器能力表限制、复用了拼接那条路已有的工具探测。代价是多一次逐帧上传（一帧 1–3MB，串行）——`stage-export.ts` 里写明了这个取舍，也写明了「中止时已上传的帧靠会话超时清理」这个已知缺口。

## 画布：叠放顺序、吸附线、锁定隐藏、套图、找节点、体检与目录

### 图层顺序：置顶 / 置底 / 上移一层 / 下移一层

这一版之前，画布上**没有层级这个概念**：节点的绘制顺序就是 `document.nodes` 的数组顺序，而那个顺序由「谁先被创建」决定，用户看不见也改不了。后果是两个，都是画布类工具里的常识性缺陷：

- 后来放上去的卡永远盖住先放的。想在一片图上写个字，字必须在图**之后**创建；否则它被压在图底下，框选也选不到，看起来像它不存在。
- 被盖住时画布只能描一条黄边说「这张被挡住了」（`geometry.ts` 的 `coveredNodes`），却不能告诉用户「把它拿到前面来」——因为拿不上来。

现在四个动作各有三个入口：右键菜单、⌘K 目录、键位（`⌥]` 上移一层 / `⌥[` 下移一层、加 `⇧` 置顶 / 置底，与 Figma 一致）。

**顺序存在数组里，不新增 `z` 字段。** 三个理由：① 老文档零迁移——数组顺序已经在磁盘上，加字段就要写迁移代码，而迁移一旦有缺口就是「用户的画布打开后遮挡关系全变」，这是最难被察觉的一类数据损坏；② 不会有「两个节点 z 相同」的并列态，任何时刻只有一条全序，置顶置底都是明确的，不需要再定 tie-break；③ 撤销栈里的一次层级调整就是一次普通的节点数组变化，不需要第二套快照。**末尾在最上面**，与 CSS 的 z-index 直觉、与 react-flow 的默认叠放一致。

**多选当刚体移动。** 选了三张卡做「上移一层」时，`layer-order.ts` 先把整组折成**一个槽位**，再让这个槽位跨过紧邻上面的那一张。逐个 `splice` 会把 a、b、c 变成 c、b、a（每次插到末尾），三张卡换了叠放次序而用户没有要求过——这种错只有在一张压着一张、又刚好有透明区域时看得出来。「整组折成槽位」之后，上移一层就是数组里一次相邻交换，正确性一眼可见。

**`coveredNodes` 跟着改了语义。** 它原来只按几何包含关系判定「谁盖住谁」，完全不看绘制顺序。层级可改之后这就是个真 bug：小卡画在大卡上面（数组里在后）明明看得见，却会被报成「被大卡完全盖住」；而用户按住「置顶」把它拿到最上层之后，提示仍然不消失——这条提示的全部价值就是告诉用户「谁压着谁、该把谁拿到前面」，指反了就是噪音。现在方向由数组下标唯一决定，同尺寸完全重合时也不再需要 id 兜底。

**关掉了 react-flow 的选中提权。** 它默认给选中的节点加内联 `z-index: 1000`，于是「置底」的那张卡一被点中就跳回最上层——用户看到的是「置底没生效」，刷新后又是对的。关掉之后叠放顺序只由数组顺序决定，`flowNodes` 也显式写下标为 `zIndex`（不靠 DOM 顺序：`onlyRenderVisibleElements` 之类的开关会重排节点元素）。代价是被压住的卡片在选中时仍可能被遮住一半——这正是用户按下「置底」时想要的结果，要编辑它就先置顶。

**真机截图捞回来的一个真问题：遮盖提示自己也被盖住了。** 那张「与「生成配置」完全重叠」的琥珀徽标原本挂在被盖住卡片的右下角——而那恰好是它最不能待的地方。「这张你看不见」这句话和那张看不见的卡一起被压在下面，以前只是靠着选中提权（拖动会选中被拖的那张）碰巧浮上来；提权一关，它就彻底消失，截图里只剩一圈也在下面的黄边。现在徽标由画布覆盖层按被盖住卡片的右下角绘制：它说的是画布层面的事实（谁压着谁），就该由画布这一层来说。坐标用世界坐标，跟着视口的平移缩放一起走，缩到 30% 时它仍在正确的位置。

### 拖动时的吸附参考线

吸附（`snapOffset`）一直都在，但它只改坐标、不留痕迹。卡片在离邻居 3px 时自己「跳」到贴边，用户看到的是一次无法解释的位移——他会以为是画布卡了一下，或者干脆把吸附关掉。

现在拖到对齐位时画一条红线，松手就消失。

**线与吸附分开算。** 吸附拿拖动原点和位移（`snapOffset(origin, others, dx, dy, threshold)`），线拿「已经落位之后」的位置（`snapGuides(landed, others)`）。写成一个函数会让「吸附算错了」和「线画错了」混在同一个返回值里，而它们的症状完全不同：前者卡在错的地方，后者卡在对的地方却画错线。

**容差是世界像素的半个像素。** 位置在拖动里被 `Math.round` 取整，所以「重合」在世界坐标里就是精确相等；留半个像素是为了吸收缩放带来的浮点误差，而不是给用户一个「差不多算对齐」的模糊带——那会让线在一堆不相干的卡片之间乱闪。真机验证过：差 1px 时不画线，差 0.5px 时画。

**同一条坐标上的多根线合并成一个区间。** 三张卡左边缘都在 x=100 时，画三条重叠的线段在视觉上是一条，但 DOM 里是三层；而用户拖过一片整齐的卡时这种情况是常态，一列排了十张就是三十层。

**只对着画面上的卡吸附与画线。** 与渲染、框选、`⌘A` 同一条纪律：对着藏起来的卡吸附，可见的那张会停在空处，而画面上没有任何东西解释它为什么停在那里；对着它画线则更糟——线上没有对应的卡。

**测试**：`smoke-canvas-geometry.mjs` 的 GG1–GG6（三条重合边各出一条线、超过半像素不画、横竖同时出现时顺序固定、无对齐不返回幽灵线、区间取并集）+ 契约组 3 条（渲染了、按吸附后的位置算、松手清空）+ 反向注入 4 条。

### 节点锁定 / 隐藏

上一版把叠放顺序交给用户之后，跟着来的第一件事就是两个更朴素的诉求：「这张我不想动」和「这张我现在不想看见」。

**锁定（`⌥⇧L`）拒绝四件事**：拖动、删除、批量删除、整理画布。锁不住 Delete 的锁等于没锁，而用户正因为相信它锁上了才敢把它留在那里。锁定的卡片仍然**可以选中**——不然就没法解锁——只是它不跟着走；批量拖动里有锁定的卡时，画布会说出跳过了几张，一次静默的「少拖了一张」在用户看来就是画布卡了。

**隐藏（`⌥⇧H`）把卡片从五个地方一起摘掉**：渲染、框选、`⌘A`、缩略图、`fitView`。这五处漏掉任何一处，症状都是「藏起来了但还是能选中」——而那种状态下按一次 Delete 就会删掉一张屏幕上根本没有的卡。**连线也必须跟着消失**：只过滤卡片会在画面上留下一条通往空气的线，它看起来像一根还没接完的连线，用户会试图去删它。

三个刻意的取舍：

1. **锁定按键按「这组里还有没锁的吗」决定方向**，混选时按下去是锁。一个真正的三态按钮（锁 / 解锁 / 部分）会让用户永远猜不准下一次按下去会发生什么。
2. **复制、粘贴、原地复制都清掉这两个标记**。复制一张锁住的卡，用户要的是「再来一份能动的」；照抄会让新卡一出生就拖不动。复制一张藏起来的卡更糟——粘贴完屏幕上什么都没有，看起来像粘贴失败。两者都是「对源卡的临时处置」，不是卡片内容。
3. **隐藏是单向门，所以必须有回来的入口**。藏起来的卡片既不在渲染里、也不在框选和 `⌘A` 里，画布上再也点不到它。两个入口：底栏那条「N 张卡片已隐藏 / 全部显示」；以及找节点（`⌘F`）——它刻意搜**全量**节点，结果行上标「已隐藏」，选中时自动把它叫回来。没有这两个入口，隐藏等于「删除，但还占着导出」。

**零迁移。** 两个标记都住在 `node.metadata` 里，老文档读出来就是「没锁、没藏」。`canvas-store` 的类型守卫按「缺项放行、类型错拒收」校验：校验器过严会让一份被外部工具写坏的文档再也存不下去。

**测试**：`smoke-canvas-node-flags.mjs` 16 条（严格 `true` 才算开、无变化时返回同一引用、顺序、`unlockedIds` 不修改入参、连线两端任意一端不可见即不画、复制走的是真实的 `cloneNodesWithCards` 而不只是 `withoutFlags` 本身）+ 契约组 9 条（一次 `mutate`、渲染与连线读同一份过滤结果、删除与拖动都过锁定、`⌥⇧` 认 `event.code`、底栏入口在、右键菜单两行在）+ 反向注入 7 条。

### 套图（提示词组）

一个配置卡上挂一组**带标题的提示词**，跑一次各出一张：正面 / 侧面 / 背面，或者一组电商图。它和已有的「生成数量」是两件事——`count` 是**同一条出 N 张**（求同，挑最好的一张），套图是 **N 条各出一张**（求异，一次出齐一套）。把两者合并会让填 3 想出三视图的人拿到三张一样的正面，所以套图住自己的字段 `node.metadata.promptSet`（上限 12 条），老文档零迁移。

- **入口在生成输入条**：参数排里的「生成数量」换成单张 / 套图 两态切换。切到套图时主输入框里已有的话带成第一条；切回单张时把第一条非空提示词写回主框，不丢字。
- **卡片上只显示只读徽标**「套图 · N 条」。编辑入口只在输入条一处——卡片上再多一个写入口，就是又一个「看起来能编辑、写入却没人读」的假入口。
- **每条独立任务**：提交时按套图跑，每条各自 `api.taskSubmit`、各自 taskId、各自占位卡、各自标题。回填按 taskId 配 asset，天然「一个任务一个占位」。
- **三条边界全在纯函数层**：空提示词条目丢弃（否则白跑一次）、标题截 24 字、超上限截断。写侧保留空条目（用户正在打字，保存瞬间消失会让光标跳走），读侧才丢。

**测试**：`smoke-canvas-prompt-set.mjs` 14 条 + 契约组 5 条（提交读草稿、每条一次 `taskSubmit` 且 `n: 1`、编辑器在 composer 而不在卡片上、多行编辑器不进参数排、locales 三块数量相等）+ 反向注入 3 条。


### 找节点（⌘F）、画布体检、整理画布

- **找节点**：一个搜索框同时搜标题、正文、提示词、模型名；中英文、全角空格、多词「都要命中」。同一张卡只出一条结果（字段按 标题 > 正文 > 提示词 > 模型 逐级退让），结果行显示的是**命中的那段原文**而不是标题——搜「樱花」命中一张叫「街景」的图时，只显示标题这一行就解释不了自己为什么在结果里。回车跳过去、选中它、并把它放进视野正中（视野计算走有单测的 `focusViewport`：0 尺寸视口、Infinity 输入、缩放夹取都在那里守住）。⌘F 原本会拉起浏览器的页内查找——在一个铺满画布的应用里，那个框永远找不到用户想找的**卡片**。
- **画布体检**：`canvas/graph-health.ts` 一次算全五类问题——环、残线、空配置、未就绪配置、孤立产物。环的判定直接复用执行器用的 `planLayers`（两份图论逻辑迟早分叉成「体检说能跑、按下却失败」）；环只描**真正在环上**的节点，不含挂在环后面的下游；残线绝不因为它把某个节点算成「有上下游」。清单出现在「运行工作流」的选项菜单里，每条都可点，点了跳到那张卡并选中；阻断项永远排在提醒项前面。
- **整理画布（⌥⇧F）**：一张有向图排成从左到右的列。分层直接复用 `planLayers`——整理出来的第 N 列就是运行时第 N 层。**有环拒绝**（环上的节点没有「第几层」，照排会得到一张井然有序却跑不起来的图）；**没接线的卡片不混进第一层**（落在流程下方两倍行距的停放带里，保持原有左右顺序）；**原地整理**（锚点是当前包围盒左上角，视野不动）；**幂等**（连按两次逐字节相同）。层内按用户原来的 `y` 排序而不是边的插入顺序。

### 全部功能目录（⌘K / 底栏放大镜）

画布的能力原来散在底栏 14 格、节点悬停条、右键菜单三处，每一处只在自己那类动作里给得全，于是「拼接视频」要先选中两段视频才看得见。现在一张 **47 行**、六个分组（添加 8 / 运行 4 / 编辑 23 / 视图 6 / 画布 4 / 帮助 2）的可搜索表把全场动作收在一起，中英文同义词都能搜（「接片」「排版」「ffmpeg」「storyboard」），↑↓ 只在能点的行之间走，回车执行。

**不可用的行不隐藏**，压暗并写明原因（「先选中至少两段视频」）——藏起来等于告诉用户「这个功能不存在」。每一行都由 `Record<CapabilityId, () => void>` 强制接上一段真代码，契约组比对目录与动作表两侧的 id，多一行少一行都红。目录**先关再执行**：留在屏幕上的遮罩会盖住它刚做的事。

### 多选对齐条

选中两张以上时，底栏上方出现一条 8 枚按钮的对齐条：左 / 水平居中 / 右 / 顶 / 垂直居中 / 底，加水平与垂直等距分布。规则全在 `canvas/align-model.ts`（21 条单测），钉住四条：

1. **只动选中**。没被圈中的卡一张都不挪——坐标、尺寸、数组顺序都不变。
2. **分组是刚体**。只选中组里一个成员时，整组按同一个整数 delta 平移，否则用户以为自己动了一张，实际把组拆了。
3. **跑到不动点**。宽度奇偶不同的卡居中时，半像素取整会让第二轮再挪一像素；第二遍按同一个按钮必须 `moved === 0`。
4. **结果全在整数格点上**。

两枚「等距」在只选中两张时压暗，并在 tooltip 里写出原因（「至少要选中三个节点」）。

**它不在 `bottom: 66px` 的原因**：第一版就是又一个绝对定位浮层，真浏览器布局守卫当场量到它在 860px 及以下压住缩放排 805–7625px²。现在拼接条与对齐条都是底栏那一行的成员、各自 `flex-basis: 100%` 独占一行，几何上不可能重叠。

**真机截图捞回来的第二条**：多选时底栏上方多出两条药丸，而生成输入条决定「翻到节点上方还是留在下方」时用的是硬编码 170px，于是它翻到节点下面、正好压在对齐条上——截图里八枚对齐按钮全被盖住，只露出左半句「对齐 2 个节点」。现在阈值加上**实测**的 `chromeHeight`（`ResizeObserver` 量底栏这一行最高的成员，因为两条药丸是条件渲染的）。

### 运行前说清哪张卡跑不了，运行后失败留在画布上

- **就绪扫描**：`canvas/readiness.ts` 把「缺什么」从卡片内的一枚徽标扩成一次全图扫描，与 `node-body.tsx` 读同一组事实（标注卡不算提示词、空 asset 不算参考图、`renderer: 'code'` 免模型渠道）。「运行工作流」旁边的箭头按钮现在写「2 个节点没准备好：缺提示词」，而不是等用户按下去、跑到一半才发现。
- **失败与被跳过是两种标记**：`canvas/run-marks.ts` 只用两种——实线红「这次失败」、虚线橙「被跳过，没跑」。只有 `completed` / `cycle` 不留痕；`cancelled` 也落痕，因为「按停之前就已经失败」的节点是真的坏了。新一轮开始时清空，单节点重试只摘自己那颗红标（下游仍没有产物，标记不能跟着清）。缩到 40% 时颜色会先糊掉，所以两种标记同时用线型和颜色区分。标记**不写进文档**：它是「刚刚这次运行」的结论，跟着导出和同步走反而不对。

### 撤销说得出「这一步是什么」，历史面板能一次退几格

- **撤销/重做按钮的 tooltip** 由 `canvas/history-model.ts`（23 条单测）把前后两份快照折成一句话：新增 / 删除 / 移动 / 编辑 / 连线 / 断线 / 分组 / 改标题 / 换背景，互相独立的两类合成「改了 N 项」。三条口径：删节点**连带**删掉的线不算第二次变化（否则 tooltip 永远说不出「撤销删除」）；新节点自带的自动连线归给新增；只动视口不报成改了节点。「整理画布」不由纯函数产出——它和「多选手拖一批节点」在两份快照里是同一件事，猜错就是撒谎。接线侧每 160ms 防抖算一次：`document` 在拖动时每帧都换对象，不防抖等于每像素 `JSON.parse` 一次几十 KB 的快照。
- **历史面板**：按住 Shift / Option 点撤销、或右键撤销，弹出这张画布的全部历史：每一步一行（「移动 3 个节点」「删除图片节点」），点一行就退回那一步。当前状态也占一行（不可点）；坏快照**截断不跳过**（`stepsBack` 是相对栈深的偏移，跳一格会让下面每行都退到错的地方）；只动视口的一步不列出。回退 N 步是**一次**文档替换而不是循环 `undo()`——栈同步改、`document` state 不是，中间帧读到的 `documentRef` 还是旧的。重做栈逐条回填，退回去之后仍能一步步走回来。
- **悬停预览**：悬停某一行时，画布上这一步会动的那几张卡描一圈虚线（`outline`，不改几何，指针扫过一列行时画布不抖；预览不写文档，否则撤销栈里会多出几十条空步骤）。退回去之后选中这一步动过的卡，并与目标文档求交。Esc、点一行、关面板三个出口都清预览。

### ⌥ 系列快捷键在 macOS 上从来没生效过

真机实测（headless Chrome + CDP 派发原生键码）确认，按住 Option 时 `event.key` 是**该布局下的组合字符**：⌥F 给 `ƒ`、⌥A 给 `å`、⌥H 给 `˙`。所以 `altKey && key === 'f'` 永远不成立——「整理画布」的 ⌥⇧F 自上线起按了没反应且不报错，源码读起来却一切正常。

全部改按 `event.code`（物理键位）。同时补上一组对齐键位：⌥⌘← / → / ↑ / ↓ 四边对齐，⌥⌘H / V 水平、垂直居中，⌥⌘E 水平等距（垂直等距没有键位——写在表里而按不出来比不写更坏）。键位只在 `ShortcutHelp.tsx` 的 `CANVAS_SHORTCUTS` 写一份，多选对齐条的 tooltip 通过 `shortcutKeysFor` 反查；目录行尾的键位徽章也读同一份表——灰行不显示徽章，等于不承诺能用。

做徽章时揪出一个一直在撒谎的文案：`canvas.duplicate` 写的是「创建副本 (Ctrl+D)」，macOS 上按的是 ⌘D，而这半句括号也不参与反查，于是目录里那一行永远没有徽章。现在文案只留动作名，键位由 `labelWithKeys` 补；`canvas.paste` 同一类问题，快捷键表里这两条也补了 `action`。

### 首次打开画布不再自带一份「已保存的画布」

以前打开画布标签页时，只要画布库是空的就立刻 `canvasCreate` 落盘一份，并塞进一对示例节点。用户从没建过它，下拉里却多一份；更糟的是空态（那排快捷卡）因此永远渲染不出来——种子固定注入两个节点，`nodes.length === 0` 从未成立。

现在首屏与「+」给的都是**内存草稿**（状态条如实写「未保存」），只有用户真往里放了东西才创建画布；删掉最后一份画布同样回到空草稿。空态第六张卡「载入示例」一次落一条 提示词 → 配置卡 的链（列间距取整理画布同一档，两卡中心线严格对齐），选中配置卡并提示「按生成就能出图」；整件事是**一次** `mutate`，撤销按一次就回到空画布。

### 顺手修掉的四处

- **测试不再往用户真实的数据目录里写画布**：`~/.dsh/dsh-imagegen/canvas/` 与测试目录只差一个 `DSH_HOME`。2026-10-13 到 10-15 三天里这样攒下 1408 条残渣，用户的画布下拉从可用变成滚不完的列表。新增 `scripts/verify-test-isolation.mjs`：扫出所有会写画布的脚本，要求它们的 `DSH_HOME` 指向 `mkdtempSync()` 建出的目录；判据是「赋值成了什么」而不是「有没有赋值」。

## 同批修掉的三个用户上报

### 局域网部署不再 403（#50）

[#50](https://github.com/q253595422/dsh-imagegen-video/issues/50)：宿主把 `webServer.host` 绑到本机网卡（`192.168.x.y`）后，插件每一条 `/api/dsh-imagegen` 都回 `403 forbidden: loopback-only`。

根因是守卫只认「连接来自回环地址」这一种权威。浏览器直连本机网卡时 `socket.remoteAddress` 就是那个网卡地址，永远不满足条件——而它本来也不该满足：客户端确实不是从回环连进来的。

现在认两种权威之一：连接来自回环，**或**请求的 `Host` 精确等于监听绑定地址。几点取舍：

- **没有加 `allowLan` 开关**。绑定地址本身就是用户的显式选择，它就该授予权威；多一个开关就多一个「开了就全放行」的误配面。
- **`0.0.0.0` / `[::]` 不授予任何权威**。它们是通配、不是某个地址，浏览器没法把它敲进地址栏，也就无从比较 Host，这种部署保持原来的 loopback-only 行为。
- **`sec-fetch-site` 与 Origin 同源检查对两种权威都照旧生效**——那才是真正防 DNS rebinding 的部分，Host 校验只是让 Origin 比较有了意义，不是替代它。
- 绑定地址按**运行时值**宽松读取，没有按类型收窄：本地 devDependency 的 `Config.host` 还只写了两个字面量，照类型写会把新宿主支持的网卡地址在类型层就抹掉。

`scripts/smoke-lan-bind-auth.mjs` 把真实路由表起在本机网卡上走真实 HTTP，10 条：

```
PASS  LAN bind: browser on the bind address is allowed
PASS  LAN bind: a foreign Host is still refused
PASS  LAN bind: foreign Host with a self-consistent Origin is still refused
PASS  LAN bind: cross-site marker is still refused
PASS  LAN bind: a mismatched Origin is still refused
PASS  loopback bind: localhost Host is allowed
PASS  loopback bind: 127.0.0.1 Host is allowed
PASS  loopback bind: a foreign Host is still refused
PASS  a bind address other than the one reached grants nothing
PASS  no bindHost: a LAN client keeps the old 403
```

最后一条是**反向控制**：不传 `bindHost` 时局域网客户端必须保持旧 403。没有它，把守卫改成「一律放行」也能让前面所有正例全绿。脚本自己探测本机非回环 IPv4，探测不到时明确 SKIP 而不是报绿。

### 多模型对比从历史打开不再空白（#49）

[#49](https://github.com/q253595422/dsh-imagegen-video/issues/49)：多模型对比生成后重启，历史里点开对比条目只显示提示词与张数，不回显图片。

数据层是好的：`history/list` 里每个成员都在、`comparisonId` 都在，取图路由对每一张都回 200。坏在聚合方式——`loadHistoryGroup` 用的是 `Promise.all`，而它是**全或无**的。对比组每个模型一个成员条目，只要**任何一个成员的任何一张图**取不到（文件被清理、一次 404、一次瞬时失败），整批就 rejected，`setImages` 与 `setBoardView` 都不执行，结果板停在那张空白上。

这解释了为什么现象像「渲染层不渲染」：它不是画错了，是根本没走到画那一步。也解释了为什么单条生成正常、只有对比出问题：单条只有一个成员，失败面是 1；四个模型的对比失败面是 4，而且重启后是从磁盘重读，比刚生成完的内存态更容易撞上。

现在逐成员 settle，一个坏成员只损失它自己。失败数**如实返回**而不是吞掉——静默少画两张，用户会读成「这次对比只出了两张」，那比报一个错更糟。界面会显示「4 个结果里有 1 个的图片读取失败，已显示其余结果」（zh/en/ru 三语）。

`scripts/smoke-history-group-images.mjs` 6 条，最后一条是反向对照：同样的输入交给旧的 `Promise.all` 折叠必须整组失败——否则断言太弱，测不出这个 bug，而那正是原来让它溜过去的原因。

### 桌面 App 里导演台顶部两颗按钮点不动

只在 macOS 桌面 App（Electron）里出现，浏览器与 web 宿主都复现不出来。宿主的窗口拖动条 `[data-window-drag]` 被 Electron 当成标题栏（`-webkit-app-region: drag`），**它不是一个 CSS 层，点在那里的事件由浏览器进程吃掉、页面根本收不到**。导演台面板是 `position: fixed; inset: 0`、`.shell` 又几乎铺满窗口，于是它最上面那一排——左栏的折叠与关闭——正好落在宿主窗口左上角那块拖动区里。

修复是给 `.shell` 补 `-webkit-app-region: no-drag`。规则挂在 `.shell` 而不是 `.root`，因为 `.root` 是 `pointer-events: none`，它根本不参与命中测试，拖动区照样赢。

为什么以前测不出来：`app-region` 在普通浏览器里是空操作，预览页、headless、web 宿主全都测不到。这次的证据是真 Electron 窗口（`titleBarStyle: 'hidden'`，与桌面版同款）里的一次真实 OS 点击——同一枚按钮、同一个坐标，不加规则时 DOM 收不到任何事件，加了之后立刻触发；同一窗口里放在拖动区外的对照按钮两种情况都正常。`verify-ui-contracts.mjs` 现在有一条源码断言守住它，并做过反向注入验证。

## 已知边界

- **3D 视口不画辅助线**（关节标记、机位视锥）。这些在 2D 版是画上去的，在 3D 里是要在场景中生成的实体，尚未补。导出（`guides: false`）与预览（`guides: true`）在 3D 下看起来一样。
- **中止导出不清理已上传的帧**。协议里只有 `stageFrame` / `stageEncode`，没有「作废一次会话」；那些帧永远等不到最后一帧、也就永不触发编码，最终靠宿主会话超时。
- **动作不做骨骼动画插值**：关键帧之间对关节做线性插值，不是贝塞尔曲线。
