# v1.7.6 · 模板库从 5 个源扩到 8 个，并修掉一个静默丢了一半条目的解析缺陷

> 各版本改动见 [CHANGELOG.md](../../CHANGELOG.md)。

这一版只有一个主题：**模板库里到底有多少条**。答案是原先的 2462 条其实少算了——
一个用编号做 key 的解析缺陷把 evolink 静默丢弃了近千条，
而这次又在 GitHub 上找到了三个可以合规接入的新来源。

## 主要更新

- **模板库：5 个源 / 2462 条 → 8 个源 / 3774 条（+1312 条，+53%）。**

- **evolink 从 462 条修复到 967 条。**
  上游那批案例的编号在不同分类文件之间**以及同一文件内部**都会重复
  （`cases/character.md` 与 `cases/portrait.md` 都从 `### Case 1:` 开始，
  图片还放在不同目录），而快照原先只拿编号当 key，
  于是约 1420 条里只有 462 条存活，其余的**没有任何报错就被覆盖了**。
  现在 id 按分类加作用域（`portrait-53`），并对同一文件内的重号去重，
  **967 条、id 零重复**。
  这不是「新增内容」而是「把本来就该在的东西修回来」，所以单列一条。

- **新增三个来源，全部按精确 commit 固定。**

  | 源 | 条数 | 许可 | 示例图 |
  |---|---|---|---|
  | `itgoyo/awesome-gpt-image2-prompt` | 602 | CC BY 4.0 | 有 |
  | `songtianlun/awesome-prompts` | 55 | MIT | 有 |
  | `youart-open-source/awesome-gpt-image-2-5-prompts` | 150 | 分层声明，见下 | **无** |

  三个源都在 `scripts/fetch-templates.mjs` 里钉死到具体 commit
  （`ITGOYO_COMMIT` / `SONGTIANLUN_COMMIT` / `YOUART_COMMIT`），
  运行时不可刷新——否则模板源一改，我们审核过的那一版就漂了。

- **来源标签行现在可以滚动。**
  八行标签在窄面板里放不下，而原先的 flex 行既不换行也不滚动：
  右边缘之后的所有来源**不可见、不可点，且屏幕上没有任何提示说它们存在**。
  现在行可横向滚动、标签不参与收缩（收缩会把标签文字和计数徽章一起截断）。
  这条用**真实浏览器**验证，而不是读 CSS 声明。

- **youart 的 150 条卡片没有缩略图，这是设计而非缺陷。**
  该语料不发自己的图片，只在每一行署名到原作者与原始帖子。
  卡片显示占位缩略图，提示词、标题与原作者链接都完整——
  它是这批来源里合规溯源最干净的一个。

- **「检测模型」不再丢掉 `nanobanana2` 和 `nanobanana2-lite`。**
  这两个 id 就在出厂默认列表 `DEFAULT_IMAGE_MODELS` 里，但
  `describeModel()` 认它们、`isLikelyImageModelId()` 不认：
  后者要求关键词后面跟分隔符，而 `nanobanana2` 里 `nanobanana` 和 `2`
  之间什么都没有。于是网关 `/models` 只返回 id、不带能力元数据时，
  面板的「检测模型」静默少两项，用户看到的是一个比目录更短的列表。
  谓词现在接受无分隔符的数字后缀（`flux2`、`wanx2` 同理），
  而 `gpt-4o`、`text-embedding-3-small` 仍然被正确排除。

## 许可

新增来源的许可与署名已逐条写入 [THIRD_PARTY_NOTICES.md](../../THIRD_PARTY_NOTICES.md)。
其中 `youart` 的许可不是一句话能说完的：该仓库按路径分层声明
（构建脚本 MIT，提示词文本不是那个项目能许可的东西——每一行都写明作者与首次出现的帖子，
仓库还用 `provenance/` 保留了各上游集合自己声明的条款）。
本版收录的行来自声明为 CC0-1.0 或 CC BY 4.0 的集合。

**`prompt-signal` 里 6 条无许可图片已清除（上一版挂起的待定项，本版定案）。**
那 6 条的 `image` 原本指向一个不声明任何许可的仓库
（`songguoxs/gpt4o-image-prompts`）。这些 URL 是**随包分发的数据**，
所以要不要提供它们由本仓库负责，而不是由聚合器负责。
现在 `image` 置空，卡片显示占位缩略图；**提示词、标题、原作者链接全部保留**，
因为这些提示词本来就逐条来自原作者自己的帖子，聚合器只提供了预览图。
生成器与检查脚本两侧都加了守卫，重新生成若忘记过滤会让构建失败。

## 包体

**安装包从 24 MiB 降到 4 MiB。** `docs/images/` 是 README 里那批截图（其中一个
13 MiB 的演示 GIF，合计约 20 MiB），运行时从不读取，GitHub 直接从仓库渲染。
它和 `docs/videos/` 一样留在仓库里、不再进安装包。CI 现在会检查这两条——
打包后用真实 `pnpm pack` 的产物核对，而不是靠人记得。

## 兼容性

- 不新增运行时依赖，无配置变更，无需迁移。
- 画布数据、历史记录、素材库、渠道设置全部不变。
- 模板收藏按 `源id:条目id` 保存。evolink 的 id 换了形态
  （`case-12` → `portrait-12`），**因此上一版对 evolink 条目的收藏会失效**；
  其余来源的 id 未变，收藏不受影响。这是修 id 冲突不可避免的代价。

  末位标签经 `elementFromPoint` 命中自身。
- 反向验证 `pnpm run test:negative` 共 **41 个变异**
  （contracts 28 + smoke 8 + video 4 + pack 1）**全部**让对应检查变红，
  本轮新增的包括「标签行不再滚动转而裁切后续标签」「标签允许收缩」
  「行高比标签还矮导致纵向切一半」「标签行不再从注册表生成」
  「注册的来源失去宿主侧抓取定义」「快照引用了来源白名单之外的主机」
  「evolink 因编号冲突再次丢条目」「快照把图片指向无许可仓库」
  「发布的归档又带上了 README 截图」「模型检测丢掉带数字后缀的族名」。
- `pack` 这一段跑的是**真实的 `pnpm pack` 产物**，不是模拟：
  在仓库副本里放一个一字节占位文件代表 `docs/images`，
  再把 `docs/images` 加回 `files`，检查必须失败。
  没有这个占位文件，缺陷会因为「副本里本来就没东西可打包」而假装通过。
- 图片主机白名单是**从真实的 `SOURCE_DEFS` 读取**再校验快照的，
  不是在测试里复制一份主机前缀——复制的那份会永远与自己一致，
  而真实网关拒绝了图片。这一条本身也有反向用例。
- 每个内置快照都断言 id 唯一，且每个非空图片引用要么是裸文件名
  （靠 `imageBaseUrl` 提供）、要么是无凭据的绝对 URL。
  URL 用解析器判断而不是正则匹配——jsdelivr 的固定 URL 路径里合法地带着
  `@commit`，把裸 `@` 当作用户信息会把 handraw 快照整个误判掉。

### 已知边界（诚实说明）

- **模板库仍然是打包随发布分发**的，不在运行时抓取——
  这是刻意的：离线可用、审核过的内容不会漂。
- 新增来源里 `songtianlun` 的图片主机白名单包含 `cdn.openai.com`，
  该主机在部分网络下不可达；不可达时卡片退化为占位缩略图，不影响提示词使用。
- `prompt-signal` 里清空图片的 6 条卡片**只有占位缩略图**，与 `youart` 的 150 条同类。
- **evolink 的收藏会失效**：见「兼容性」一节。
