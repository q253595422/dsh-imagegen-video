# v1.13.0 — 视频生成前先做一轮导演规划

一句话概括：视频不再「输入提示词就直接生成」——生成前先推理一轮，把需求拆成镜头、动作、运镜、时长与风格，而这些结果**就是**实际发给模型的提示词和参数。

## 为什么

旧链路里 `request.prompt` 原样进入上游请求体。写「两个人在咖啡馆门口相遇」，模型收到的就是这七个字：没有景别、没有运镜、没有时间结构，参数也是面板默认值。这不是提示词写得不好，是中间少了一步。

## 做了什么

- **导演规划（`src/video-director.ts`）**：把一句话拆成镜头列表，产出最终提示词与 `seconds / aspectRatio / resolution`。
- **接进唯一汇聚点 `runVideo`**：面板、画布、分镜、Agent 工具、工作流执行器都经过这里，一处接入全线生效。
- **参数只收紧、不放宽**：用户选的值是上限；规划提议的参数还要再按模型协议族收敛（如算力萌只接受 16:9 / 9:16 / 1:1）。
- **预览即提交**：`POST /api/dsh-imagegen/video/plan` 只跑规划不渲染；提交时带上这份预览，宿主不重新问对话模型，避免「看的是一版、发的是另一版」。
- **降级有据**：未配置对话模型、端点不可达、超时、返回不是合法 JSON，一律退回离线镜头规划，并标明来源与原因，记入新的 `video-plan` 诊断阶段。
- **输入边界**：空输入 `video-prompt-empty`；超 4000 字符 `video-prompt-too-long`，两者都不会提交到上游。

## 计划记录在哪里

- 任务摘要（`VideoTaskSummary.plan`）：渲染中就能看到规划；
- 视频历史（`VideoHistoryEntry.plan`）：事后能解释「为什么是 10s / 9:16」；
- 诊断面板：规划降级时留一条 `video-plan` 记录。

## 提示词结构依据

沿用 Wan 2.2 官方 `--use_prompt_extend` 的电影语言（景别、光线、运镜、风格；图生视频强调动作而非复述静帧）。选它的理由见 README 的选型说明：Apache-2.0、无需私有服务，且本插件的 `wan2.2-*` 渠道正是这条协议族。

## 验证

- `pnpm test`：219 项通过（含新增 `pnpm test:director` 的 13 项）。
- 端到端实测：真实对话模型产出镜头规划 → 提交时采用同一份预览 → 算力萌真实渲染 5 秒成片 → 历史中保存了规划，上游收到的提示词与预览逐字一致。

## 配置

规划复用「设置 → 提示词增强模型」的 `promptModel`，`promptApiUrl` / `promptApiKey` 留空时复用生图渠道。**无需新增密钥**。留空 `promptModel` 时退回离线规则规划，视频照常生成。
