# v1.30.0 — 模型能力改为内置基线表；修好聚合网关模型被误判为未知协议

本版做两件事：把「哪些模型 id 属于哪个协议族、它还该不该被推荐」从代码分支搬进**一张内置数据表**，并顺手修掉表一建立就暴露出来的一个线上误判——用聚合网关的用户，官方预设当时是被当成「未知协议」处理的。

## 为什么是内置表，而不是远程拉取

能力目录全部内置，插件**不为它发任何网络请求**。上游弃用一个模型时，发一个小版本更新基线表即可：用户不需要联网同步，也不会多出一个「目录接口挂了导致面板不可用」的故障面。

代价是表会滞后于上游，所以判定留了三层（见下），新出的 id 不会因为表里没写就被当成不认识。

## 结构

- **新增 `src/model-baseline.ts`。** 此前每加一个协议族都要在 `describeModel` 的 if 链上添一段、每出一个新模型 id 都要改代码，而这两件事与「请求怎么拼」本来无关。现在表里一行一个 id，弃用与请求逻辑分开评审、分开回溯。
- **`ModelFamily` 的联合类型定义搬到这个文件**，`model-catalog.ts` 改为再导出，避免出现两份会各自漂移的声明。

## 修掉的误判

聚合网关按 `vendor/model` 寻址（`google/gemini-3-pro-image`、`openai/gpt-image-2.5`）。旧实现拿原始串直接比对，于是**本仓库自带的 OpenRouter 预设落到 `unknown`**：

- 面板把它当成「只能带 1 张参考图」，一有第二张就警告会丢图；
- engine 退回通用 OpenAI 协议，该族真正的请求形态没被用上。

现在查表前剥掉一层厂商前缀。**只剥一层**：`a/b/c` 得到 `b/c`，`image-01` 这类本来没有前缀的 id 不受影响，`/gpt-image-2` 这种首字符就是分隔符的也不会被吃掉。把本仓库的默认模型列表与全部渠道预设过一遍，**unknown 从 1 条降到 0 条**。

## 三层判定，顺序是重点

1. **基线表精确命中**——唯一能报生命周期的层，因为它有可追溯的来源。
2. **命名约定归族**——表里没写、但族名对得上（`gpt-image-2.7-sunburst`、`seedream-6.0`）的 id 照常归族。上游出后缀比任何人维护表都快，这一层保证表不需要逐版追新。
3. **真的认不出才 `unknown`**，仍走尽力而为的通用请求，不拒绝。

## 生命周期提示：是提示，不是拦截

表里标了 `deprecated` / `removed` 的 id，会在模型选择器下方显示一行说明；有替代品时点名建议改用哪个。用主题里真实存在的 `state-warn` / `state-error` token（`--dsw-alias-state-warn-primary`、`--dsw-alias-state-error-primary`），三语齐备。

**请求照发、不改写、不禁用。** 用户可能挂在中转站上，那边仍在服务一个原厂已经下线的模型；把这个流程硬拦下来，等于弄坏一件本来能跑的事。这条边界在测试里单独钉了一条。

## 刻意不写自动关停日期

本轮本想连关停日期一起内置（`gpt-image-1`、`gpt-image-1.5`、`gemini-2.5-flash-image` 等），实际去核对时 **OpenAI 与 Google 的官方弃用页从构建环境三个入口都拿不到**：`developers.openai.com` 与 `platform.openai.com` 返回 403（`x-vercel-mitigated: deny`），`ai.google.dev` 连接超时；换普通搜索结果，返回的全是 SEO 站，没有一条能追到原始记录。

日期是整页里最容易变、又最无法在本机验证的一项。写错比不写更有害：要么劝退一个还能用的模型，要么承诺一个已经结束的支持。所以：

- `lifecycle` 只记录**已经发生**的状态，不记录「计划中的日期」；
- 每条非 `active` 记录都必须写明 `source`，测试强制检查，方便下一个人复核而不是照信；
- **目前表里没有任何一条被标为弃用**——没有可靠证据就不编。

机制就位、数据等证据，这是本版有意留下的状态。

## 测试

- 新增 `scripts/smoke-model-baseline.mjs`（22 条）：厂商前缀剥离（含只剥一层、空段、大小写）、三层判定、基线表自身的一致性（无重复 id、全小写、非 active 必有 `source`）、生命周期到文案 key 的四种映射、以及「弃用不拦截请求」这条边界。
- 接入 `pnpm test`，并在 `test:negative` 里新增 `baseline` 组。
- **两条反向用例实证能变红**：把前缀剥离退回 `return id`、把默认生命周期改成 `deprecated`，各自让对应用例失败。跑出 `2/2 defects turn the check red`。
- `smoke` 另加一条真机（jsdom 渲染真实面板）断言：**活跃模型不得出现生命周期提示**。误报的代价是让用户习惯性忽略这一行，等它哪天说真话时已经没人看。

## 边界如实说明

- 表里的族判定与能力标注是照着现有协议实现填的，**没有对每个 id 逐一发起真实调用验证**。
- 生命周期提示的**正向分支目前没有真实数据可渲染**，只有纯函数层（`lifecycleNoticeKey`）测到；面板那条渲染分支在表里出现第一条弃用记录之前不会被执行。这是本版已知的未覆盖点，写在这里而不是留给人去发现。
- `video-model-catalog.ts` 是视频侧独立的一张表，本版**没有合并**它：视频族的能力维度（模式、分辨率、是否需要参考图）与图像侧不同，强行合成一张会让两边都长出用不到的字段。合并与否留到确实需要共享判定时再定。
