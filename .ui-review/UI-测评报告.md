- 测评对象：`@q253595422/dsh-imagegen-video` v1.15.1，面板品牌名 **VisioWork**
- 测评实例：`dsh uireview --port 4790 --host 127.0.0.1 --no-open`（独立 profile `uireview`）
- 测评日期：2026-10-21
- 方法：Chromium CDP 真实驱动（`Input.dispatchMouseEvent` / `Input.dispatchKeyEvent` / `DOM.setFileInputFiles`），逐模块点击、输入、上传、键盘操作；**未修改 `src/` 任何代码**
- 截图：263 张，全部在 `.ui-review/shots/`，本报告逐条对应
- 浏览器：1600×1000 为主，另测 1280 / 1024 / 900 / 760 宽

## 一、结论先行

**核心问题只有一个，但它很致命：文生图生成失败时，界面上什么都没发生。**

点「开始生成」→ 按钮变成「生成中… 已用时 0s」→ 1.5 秒后按钮恢复成「开始生成」，可以再点。
没有任何红字、没有 toast、没有任务条目、没有失败计数。用户唯一的感受是「点了没反应，再点一次还是没反应」。
失败原因只在「诊断日志」里能看到（`HTTP 400 Model agnes-image-2.1-flash is not supported…`）。

对照组：**生视频走同一套链路，失败会在面板里显示红字错误**（截图 `shots/275-234-m8j-video-5s.png`）。
同一份代码库里两条链路的错误反馈不一致，说明生图这条漏了。

除此之外，三条 P0/P1 级别的缺陷：
- **侧边栏搜索框完全不起作用**（输入任意关键词，历史记录一条都不少）
- **渠道配置「保存」既不校验也不反馈，配置不落盘**
- **无限画布项目下拉 1425 条、1417 条重名、没有搜索框**

## 四、明确的 bug / 走不通的流程（含复现步骤）

### BUG-1｜文生图生成失败完全静默 ⚠️ 最严重

1. 打开插件，进入「普通生图」
2. 在提示词框输入任意内容（如 `a red apple on a wooden table`）
3. 渠道选择 `11 / agnes-image-2.1-flash`

5. 观察：按钮变「生成中… 已用时 0s」→ 约 1.5s 后恢复「开始生成」→ 界面无任何变化，无错误、无任务条目

## 五、做得对的地方（避免改坏）

- **图片转 PPT 配置弹层**的对话框语义是全站模板：`role=dialog` + `aria-modal=true` + 可读 `aria-label` + Esc 关闭 + 焦点进入首按钮。其它三个弹层/面板应照此对齐。
- **生视频的失败反馈**（红字 + HTTP 状态 + 取消按钮）是正确形态，生图应复刻。
- **窄窗适配**：1280 / 1024 / 900 / 760 四档下，五个工作区**均无横向溢出**，页面不出现横向滚动条。
- **密钥字段**：`type=password` + 「已配置 — 输入新值可替换」+ 显示/清除，符合预期。
- **画布快捷键面板**的 `?` / F1 触发与内容组织（视图 / 选择 / 编辑 / 节点 + 脚注）写得好，只缺 ARIA 语义。
- **诊断日志**的「记录仅保存在本机内存中，密钥已脱敏」说明到位。
- **加载态**：生图有 spinner + 「正在加入生成队列… 已用时 0s」；生视频有「生成中 已用时 0s」+ 取消。
